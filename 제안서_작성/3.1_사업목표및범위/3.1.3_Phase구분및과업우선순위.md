# Ⅲ.1.3 Phase 구분 및 과업 우선순위

> **메타** | 요구사항: `GM-01, GM-06, GM-07, GM-08` | Phase: Phase1·Phase2·전기간 | 예상 분량: 2장

---

## 1. 거버닝 메시지

> **Phase1의 임계경로는 문서 작성이 아니라 「합의와 승인」이므로, 우선순위는 산출물의 분량이나 난이도가 아니라 「외부 데드라인 종속도 × 상대방 동의 필요성 × 내부 승인 주기」 세 축으로 결정하고, 이 세 축 모두에 걸린 3건을 먼저 착수한다.**

- **서브메시지 1** — 우선순위 결정 기준을 먼저 선언하고 그 기준으로 Phase1 산출물 9건을 정렬한다. 기준 없는 순서 나열은 착수 후 이견이 생겼을 때 조정 근거가 되지 못한다.
- **서브메시지 2** — Phase1의 진짜 병목은 **책무구조도(내부 승인)·비용배분 협의서(중앙회 합의)·금보원 실사자료(외부 일정)** 3건이다. 이 3건은 제안사가 아무리 빨리 써도 제안사 힘만으로 끝나지 않으므로, 착수 첫 주에 상대방을 협의 테이블에 앉히는 것을 첫 과업으로 삼는다.
- **서브메시지 3** — Phase2는 Phase1의 산출물을 입력으로 받아 확장하는 구조다. Phase1에서 만든 위험평가 기준·라이프사이클 초안·계측 요건이 없으면 Phase2 과업은 시작 지점을 잃는다.

## 2. 본문

### 2.1 우선순위 결정 기준 — 4개 축

과업 우선순위는 다음 4개 축의 값을 매겨 결정한다. 축의 순서 자체가 가중치 순서다.

| 순위 | 축 | 판정 질문 | 값 |
|---|---|---|---|
| 1 | **외부 데드라인 종속도** | 이 산출물이 늦으면 10월 개시·금보원 점검·금감원 보고 중 무엇이 밀리는가? | 직접 종속 / 간접 종속 / 무관 |
| 2 | **상대방 동의 필요성** | 제안사와 발주처만으로 완결되는가, 제3자(중앙회·감독기관)의 동의가 필요한가? | 외부기관 동의 / 중앙회 합의 / 발주처 내부만 |
| 3 | **내부 승인 소요기간** | 이사회·위원회 등 정기 회의체 상정이 필요한가? 상정 주기는? | 이사회 / 위원회 / 부서 전결 |
| 4 | **선후행 의존** | 이 산출물이 다른 산출물의 입력인가? | 선행 필수 / 병행 / 후행 |

**이 순서를 채택한 이유** — 축 4(선후행 의존)를 1순위로 두는 전통적 일정 수립 방식은 모든 작업을 제안사가 통제한다는 전제 위에 선다. 본 사업은 그 전제가 성립하지 않는다. 제안사가 통제하지 못하는 요소(외부 일정, 상대방 동의, 회의체 주기)가 임계경로를 지배하므로 통제 불가 요소를 상위 축에 둔다.

### 2.2 Phase1 산출물 9건의 우선순위 정렬

| 착수순위 | 산출물 | 외부 종속 | 동의 필요 | 내부 승인 | 선후행 | 착수 시점 | 판정 근거 |
|---|---|---|---|---|---|---|---|
| **1** | **DL1-2** AI 책무구조도(AI 책무 반영) | 간접 | 발주처 내부 | **이사회** | 선행 필수 | **D+1** | 이사회 상정 주기가 임계경로를 결정. 문안 확정 후에도 상정→의결까지 최소 1주기 소요 |
| **2** | **DL4-1** AI서비스 비용 배분 기준안 및 협의서 | 간접 | **중앙회 합의** | 위원회 | 병행 | **D+1** | 상대방 서명이 필요한 유일한 산출물. 협의 착수가 늦으면 만회 수단이 없음 |

| **7** | **DL1-4** AI기본법 위반 여부 점검 보고서 | 간접 | 발주처 내부 | 부서 전결 | 병행 | **D+15** | 법령 대조 작업이므로 상대방 의존 없음. 3개 과제 사양 확보 후 즉시 수행 |

**정렬 결과의 의미** — 착수 순위 1·2위는 **분량이 가장 적은 산출물**이다. 반면 최종 산출물인 DL1-5는 가장 늦게 착수한다. 이는 *"쓰기 어려운 것을 먼저 쓴다"* 가 아니라 *"내 힘으로 끝나지 않는 것을 먼저 건다"* 는 원칙의 결과다.

### 2.3 Phase1의 진짜 병목 3건

#### 병목 ① DL1-2 책무구조도 — 내부 승인이 임계경로

책무구조도는 「금융회사의 지배구조에 관한 법률」에 따라 각 임원별 내부통제 책임을 배분한 문서이며, 금융감독원 AI RMF는 여기에 **「AI 관련 내부통제 및 위험관리 등」에 관한 책무를 반영**하도록 제시한다(AI RMF 참고자료 「책무구조도에 AI 관련 책무 반영」). 문제는 이 문서가 **임원 개인의 법적 책임 범위를 바꾸는 문서**라는 점이다.

- **임계경로 구성** : 현행 책무구조도 입수(D+3) → AI 책무 배분안 작성(D+10) → 해당 임원 개별 협의(D+17) → 준법·감사 검토(D+24) → 이사회 상정 마감(D+30) → **이사회 의결(D+35 [가정])** → 책무기술서 개정 등록
- **왜 병목인가** : 이사회는 통상 월 1회 개최되므로 상정 마감을 한 번 놓치면 **한 달이 통째로 밀린다.** Phase1이 2개월이므로 1회 지연이 곧 Phase1 실패다.
- **대응** : 착수 D+1에 이사회 개최 일정과 상정 마감일을 확정하고, 그 날짜에서 역산해 협의·검토 일정을 고정한다. 임원 개별 협의는 순차가 아니라 **동일 주간 병렬 면담**으로 설계한다.

#### 병목 ② DL4-1 비용 배분 협의서 — 상대방 서명이 임계경로

비용 배분은 **양 기관의 손익에 직접 영향을 주는 유일한 산출물**이다. 논리적 타당성만으로 서명이 나오지 않는다.

- **임계경로 구성** : 협의체 구성 및 1차 회의(D+7) → 배분 방식 대안 3안 제시(D+17) → 기관별 시산 결과 회람(D+24) → 쟁점 조정 회의(D+31) → 권고안 확정(D+38) → 부속협약 별지 문안 확정(D+45) → **양측 서명(D+55)**
- **왜 병목인가** : 중앙회의 의사결정 절차(내부 품의·상호금융 관련 회의체)는 제안사도 발주처도 통제하지 못한다. 또한 시산 결과가 어느 한쪽에 불리하게 나오면 재협의가 발생한다.
- **대응** : 대안을 1안이 아니라 **3안(균등분담 / 예상사용량 기준 / 혼합)으로 제시**하여 협의를 "찬반"이 아니라 "선택"으로 전환한다. 각 안의 기관별 분담액을 시산해 함께 제시하여 회의 1회당 결론 도달 확률을 높인다. 상세 산식은 Ⅲ.4.5.

#### 병목 ③ DL2-2 금보원 실사자료 — 외부 일정이 임계경로

금융보안원 보안성 검토 일정은 발주처가 신청하되 확정은 심사기관이 한다.

- **임계경로 구성** : 3개 과제 사양·아키텍처 확보(D+3) → 보안대책서 초안(D+17) → 자체 사전점검(D+24) → 보안대책서 확정(D+31) → 실사자료 패키지 제출(D+38) → **현장점검 대응(D+45~ [가정])** → 보완 회신(지적 발생 시 5영업일 내)
- **왜 병목인가** : 현장점검 일자가 뒤로 밀리면 10월 개시일과의 여유가 줄고, 앞으로 당겨지면 준비 기간이 줄어든다. 어느 방향이든 제안사가 통제하지 못한다.
- **대응** : 실사자료를 **점검일 기준이 아니라 「사양 확보일 + 35일」 기준으로 완성**하여 점검일이 앞당겨져도 대응한다. 자체 사전점검은 「금융분야 인공지능 보안 안내서」 제7장(보안성 검증 절차 및 방법) 및 가이드라인 보안성 원칙 점검항목 38개를 기준으로 수행한다.

### 2.4 Phase1 → Phase2 입력·출력 연결

Phase2 과업은 Phase1 산출물을 입력으로 받는다. Phase1이 부실하면 Phase2는 다시 만드는 데 시간을 쓴다.

| Phase2 과업 | 입력받는 Phase1 산출물 | 입력의 성격 |
|---|---|---|
| DL1-6 AI 위험관리업무 매뉴얼 | DL1-1(준칙), DL1-3(실제 평가 사례 3건) | 규정 조문 + **실제로 한 번 돌려본 평가 기록**이 매뉴얼의 예시가 된다 |
| DL1-7 AI 데이터 거버넌스 정의서 | DL1-1(업무규정 중 데이터 조항), DL2-1(보안대책서의 데이터 통제) | 데이터 관리 원칙과 보안 통제 수준 |
| DL1-8 AI 거버넌스 실효성 검증 보고서 | DL1-5(승인서 발급 이력), DL1-3(위험평가서) | **시뮬레이션 대상이 곧 Phase1에서 처리한 3개 과제**다 |
| DL2-3 라이프사이클 표준 정의서 | DL1-5 발급 과정에서 실제로 밟은 절차 | Phase1의 실행 경로가 표준의 초안이 된다 |
| DL2-5 성과측정 프레임워크 | DL1-3(서비스별 위험요소·통제항목) | 통제항목이 모니터링 지표의 후보군 |
| DL3-1 플랫폼 진단서 | DL1-3(위험등급 체계), DL4-1(계측 요건) | 진단 시 측정할 항목의 정의 |
| DL3-2 목표 아키텍처·로드맵 | DL4-1(정산 변수) | 계측 설계의 요건 |

**핵심 연결 3개를 문장으로 고정한다.**
1. Phase1에서 **3개 과제에 위험평가를 실제로 실시한 기록**이 Phase2 위험관리 매뉴얼의 예시와 실효성 검증의 대상이 된다.
2. Phase1에서 **거버넌스 승인서를 발급하며 밟은 절차**가 Phase2 라이프사이클 표준의 뼈대가 된다.
3. Phase1에서 **합의한 정산 변수**가 Phase2 플랫폼 계측 설계의 요건이 된다.

### 2.5 AI 운영플랫폼 구축사업과의 연계 우선순위 준수 (GM-01)

본 사업은 컨설팅이고 플랫폼은 별도 구축사업이므로, 두 사업의 산출 시점이 어긋나면 설계서가 구축에 반영되지 못한다. 다음 세 가지 규칙으로 연계 우선순위를 준수한다.

1. **요건 전달 시점을 구축사업 일정에 맞춘다.** 구축사업의 설계 단계 착수일을 착수 2주 내 확인하고, 그 시점 이전에 **가드레일 기능 요건·계측 요건·게이트 연동 요건 3종을 선(先)전달**한다. 최종 설계서(DL3-2) 완성을 기다리지 않는다.
2. **구축사업이 이미 확정한 기술 결정은 제약조건으로 수용한다.** 클라우드 구성, 모델 서빙 방식, 인증·권한 체계가 이미 결정되어 있으면 목표 아키텍처를 그 위에서 설계하고, 변경이 필요한 항목은 **「변경 요청 목록」으로 별도 제시**하여 구축사업이 판단하도록 한다.
3. **합동 점검 회의를 격주 1회 운영한다.** 본 사업 PM과 구축사업 담당 조직이 참여하여 요건 반영 여부를 확인하고, 미반영 항목은 사유와 대안을 회의록에 남긴다.

## 3. 제안서용 요약 · 논리 구조

**논리 골격 : [기준 선언] → [정렬] → [병목 지목] → [연결] → [연계 준수]**

- **[기준 선언]** 우선순위 4개 축 = ① 외부 데드라인 종속도 ② 상대방 동의 필요성 ③ 내부 승인 주기 ④ 선후행 의존
  - **통제 불가 요소를 상위 축에 배치** ← 전통적 선후행 우선 방식과의 차이점
- **[정렬]** Phase1 산출물 9건 착수 순서 : **DL1-2 → DL4-1 → DL2-2 → DL2-1 → DL1-1 → DL1-3 → DL1-4 → DL4-2 → DL1-5**
  - 1·2순위가 분량 최소 산출물 → *"쓰기 어려운 것"이 아니라 "내 힘으로 안 끝나는 것"을 먼저*
- **[병목 지목]** **3건 = 책무구조도(이사회) · 비용배분 협의서(중앙회 서명) · 금보원 실사자료(외부 점검일)**
  - 공통점 : **작성 시간이 아니라 합의·승인 시간이 임계경로**
  - 대응 : 이사회 상정 마감 역산 고정 / 대안 3안 + 시산 동시 제시 / 점검일 무관하게 "사양 확보 +35일" 완성
- **[연결]** Phase1 → Phase2 입력 3개 고정 : 실시한 위험평가 → 매뉴얼 예시·검증 대상 / 밟은 승인 절차 → 라이프사이클 뼈대 / 합의한 정산 변수 → 계측 설계 요건
- **[연계 준수]** 구축사업 대응 3규칙 : **요건 3종 선전달 / 확정 기술은 제약조건 수용 + 변경요청 목록 분리 / 격주 합동 점검**

## 4. 시각적 표현 방안

### (a) 슬라이드 분할 구조 — 2장

- **1장 : `상하 2분할`** — 위 = 우선순위 2×2 매트릭스(산출물 9건 배치), 아래 = 착수 순서 정렬표
- **2장 : `좌우 2분할 비교`** — 왼쪽 = 병목 3건 확대 카드, 오른쪽 = Phase1→Phase2 입력·출력 연결도

### (b) 도해 지시

**1장 상단 — 우선순위 2×2 매트릭스**
- 가로축 = **외부 데드라인 종속도**(좌 = 무관 → 우 = 직접 종속)
- 세로축 = **합의·승인 난이도**(하 = 부서 전결 → 상 = 이사회·외부기관)
- 9건의 산출물을 원형 노드로 배치, 노드 크기는 예상 작성 분량에 비례
- **우상단 사분면을 적색 음영 처리**하고 "임계경로 구역" 라벨. 여기에 DL1-2·DL4-1·DL2-2 3건이 들어간다
- 각 노드에 착수 시점 배지(D+1, D+3, D+5 …)
- 좌하단 사분면에는 "여유 구역" 라벨과 DL4-2·DL1-4 배치 — 대비를 통해 우상단의 긴급성을 강조
- 매트릭스 우측 여백에 세로 범례 : 노드 색상 = 산출물 계열(DL1 거버넌스 / DL2 라이프사이클·당국 / DL4 비용)

**1장 하단 — 착수 순서 정렬표** (아래 표1)

**2장 좌측 — 병목 3건 카드 (세로 3단)**
- 카드마다 4개 슬롯 : `병목 이름` / `임계경로 타임라인(가로 소형 막대, 마일스톤 마름모 표시)` / `왜 병목인가 1문장` / `대응 1문장`
- 타임라인 막대에서 **제안사가 통제하지 못하는 구간을 빗금(斜線) 패턴**으로 칠한다. 세 카드 모두에서 빗금 구간이 막대 후반부를 차지하는 모습이 드러나야 한다 — 이것이 이 슬라이드의 핵심 시각 메시지
- 카드 우측 상단에 통제 불가 주체 배지 : `이사회` / `중앙회` / `금융보안원`

**2장 우측 — Phase1 → Phase2 연결도**
- 좌열에 Phase1 산출물 9건, 우열에 Phase2 산출물 10건을 세로 나열
- 두 열 사이를 화살표로 연결. **입력 관계가 있는 선만 그리고, 없는 항목은 연결선 없이 둔다**
- 굵은 화살표 3개(핵심 연결 3개)만 강조색, 나머지는 회색 세선
- 하단에 Phase 경계선(D+60)을 세로 점선으로 표시

### (c) 표·차트 사양

**표1. Phase1 산출물 우선순위 정렬표**

| 컬럼 | 내용 |
|---|---|
| 착수순위 | 1~9 |
| 산출물 번호·명칭 | DL 번호 |
| 외부 데드라인 종속도 | 직접 / 간접 / 무관 |
| 상대방 동의 | 외부기관 / 중앙회 / 발주처 내부 |
| 내부 승인 | 이사회 / 위원회 / 부서 전결 |
| 선후행 | 선행 필수 / 병행 / 후행(의존 대상) |
| 착수 시점 | D+n |
| 판정 근거 | 1문장 |

- 행 예시 1 : `1 | DL1-2 AI 책무구조도 | 간접 | 발주처 내부 | 이사회 | 선행 필수 | D+1 | 이사회 상정 주기가 임계경로를 결정`
- 행 예시 2 : `9 | DL1-5 거버넌스 승인서 | 직접 | 발주처 내부 | 위원회 | 최종 후행 | D+45 | 앞의 모든 산출물이 입력, Phase1 종착점`

**표2. Phase1 → Phase2 입력 연결표** (2장 우측 하단 또는 별지)

| 컬럼 | 내용 |
|---|---|
| Phase2 과업·산출물 | DL 번호 |
| 입력받는 Phase1 산출물 | DL 번호 |
| 입력의 성격 | 무엇으로 쓰이는가 |

- 행 예시 1 : `DL1-8 실효성 검증 보고서 | DL1-5, DL1-3 | 시뮬레이션 대상이 곧 Phase1에서 처리한 3개 과제`
- 행 예시 2 : `DL3-2 목표 아키텍처·로드맵 | DL4-1 | 정산 변수가 계측 설계의 요건`

## 5. 인접 절과의 경계 / 인용 근거

### 경계 자기점검

- **Ⅲ.2.2(Phase1 데드라인 역산 전략)로 넘긴 것** : 10월 개시일에서 역산한 마일스톤 캘린더, 버퍼 배치 설계, 조기 인수 2단계 방식, 금보원·금감원 일정 변경 시 재조정 규칙. 본 절은 **"무엇을 먼저 하는가와 그 판단 근거"** 만 기술했고, 역산 캘린더는 그리지 않았다.
- **Ⅳ.4(추진일정)로 넘긴 것** : 사업 전체 마스터 일정표, 단계별 소요자원 분배, 월별 투입인원.
- **Ⅲ.2.5(위험요소)로 넘긴 것** : 병목이 실제로 지연되었을 때의 대응 시나리오. 본 절은 병목의 **식별과 착수 순서**만 다뤘다.
- **Ⅲ.4.5로 넘긴 것** : 비용 배분 대안 3안의 내용과 산식.
- **Ⅲ.4.3.5로 넘긴 것** : 금보원 실사자료의 구체적 목록과 현장점검 대응 방법.
- **본 절이 인접 절보다 앞서 확정하는 것** : 우선순위 결정 기준 4개 축. Ⅲ.2.2와 Ⅳ.4는 이 기준을 재정의하지 않고 그대로 사용한다.
