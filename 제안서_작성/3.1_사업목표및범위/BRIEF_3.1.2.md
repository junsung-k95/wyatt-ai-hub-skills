## 1. 이 문서가 답해야 할 질문

> **과제 4개가 서로 어떻게 맞물려 하나의 결과물이 되는가, 그리고 우리 책임의 경계는 어디까지인가?**

이 질문에 답하지 못하면 분량과 무관하게 실패한 문서다.

## 2. 반드시 본문에 들어가야 할 것

1. 과제1~4 각각의 **범위 1줄 정의 + 핵심 산출물**
2. **과제 간 의존관계를 명시적으로 서술.** 최소 다음 3개는 반드시 다룰 것 — ① 과제1의 위험평가체계·준칙이 과제3의 가드레일 플랫폼으로 시스템화된다 ② 과제2의 라이프사이클 단계 정의가 과제3의 통합관리 기능 요건이 된다 ③ 과제4의 비용배분 기준이 Phase1 업무위수탁 부속협약의 별지가 된다
3. **책임한계(Scope In / Scope Out)를 표로.** 특히 Scope Out에 대해서는 '왜 제외인가 + 대신 무엇을 지원하는가'를 함께 적을 것 (예: 시스템 구축 개발 자체는 별도 사업, 본 사업은 요건·설계까지)
4. 산출물이 **은행용 / 중앙회(상호금융)용으로 각각 작성·검수**된다는 점을 범위 정의에 반영 (실질 산출 개수가 2배)
5. 협력업체가 있을 경우 어느 과제를 맡는지 (없으면 '주사업자 단독 수행'으로 명시)
