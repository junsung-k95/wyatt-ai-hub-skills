# Ⅲ.1.4 RFP 요구사항 대응 총괄표

> **메타** | 요구사항: `FM-01, GM-13` | Phase: 전기간 | 예상 분량: 1장

---

## 1. 거버닝 메시지

> **제안서가 RFP를 빠짐없이 읽었다는 것은 선언이 아니라 대조표로 증명해야 하므로, RFP 전문을 요구사항 257건으로 분해해 ID를 부여하고 각 ID가 제안서 어느 소절에서 답변되는지를 매핑한 추적표를 제시하며, 이 ID 체계를 착수 후 산출물 검수 기준으로 그대로 승계한다.**

- **서브메시지 1** — RFP를 13개 카테고리 **257건**으로 분해했고, 제안서 본문이 응답해야 할 **203건 전건이 목차에 매핑되어 미매핑 0건**이다. 나머지 54건은 본문 응답 대상이 아닌 제출 실무·평가 절차 요건이며 별도 체크리스트로 관리한다.
- **서브메시지 2** — 전수 대조표는 지면 제약상 별첨1로 넘기고, 본 절은 **카테고리 × 제안서 목차 커버리지 매트릭스**만 제시하여 평가위원이 한 화면에서 밀집도와 공백을 확인하도록 한다.
- **서브메시지 3** — 이 ID 체계는 제안서 작성용 도구로 끝나지 않는다. 착수 후 **산출물 검수 기준(PD-IV-3c)의 판정 단위**로 승계하여, "요구사항 ID 단위로 충족 여부를 확인하는" 검수 방식을 운영한다.

## 2. 본문

### 2.1 요구사항 분해 방식

RFP 전문(Ⅰ 사업개요 ~ Ⅳ 제안서 작성요령 및 서식)을 문장 단위로 분해하여 **개별적으로 충족 여부를 판정할 수 있는 최소 단위**를 요구사항 1건으로 정의했다. 분해 원칙은 세 가지다.

1. **한 문장에 요구가 둘이면 둘로 나눈다.** 예: *"보안대책을 마련하고 금융보안원 보안성 심사를 준비"* → `OBJ-03`(보안대책 마련), `OBJ-04`(보안성 심사 준비)로 분리. 충족 시점과 산출물이 다르기 때문이다.
2. **접두어로 성격을 구분한다.** 접두어 자체가 대응 방식을 지시한다(아래 2.2 표).
3. **참고·조건부 요건도 누락하지 않고 ID를 부여하되 유형을 표시한다.** 유형은 `필수` / `조건부` / `제안재량` / `참고` 4종이며, `참고`는 응답 의무가 없으나 인지 여부를 확인하기 위해 등재한다.

**즉, 본문에서 답해야 할 203건에 대해 미대응 0건이다.** 전수 대조표(요구사항 ID / RFP 원문 / 유형 / Phase / RFP 출처 페이지 / 대응 제안서 목차)는 **별첨1 「RFP 요구사항 추적표」** 로 제출한다.

> **[확인 필요 사항]** 요구사항 추적표 v0.1의 카테고리별 집계(과업요구사항 105건 + 제안·행정요건 152건 = 257건)를 재검산한 결과, 본문 응답 대상은 **203건**이다. 제안서 최종본 제출 전 별첨1과 본 표의 수치를 재대조하여 일치시킨다.

### 2.4 매핑 밀집도가 알려주는 것

카테고리 × 목차 매트릭스를 그리면 **요구사항이 몰려 있는 구간과 비어 있는 구간**이 드러난다. 이는 지면 배분의 근거가 된다.

- **최밀집** : `Ⅲ.4.2`(과제1, 23건) · `Ⅲ.4.3`(과제2, 21건) · `Ⅲ.4.6`(산출물·소유권, 23건) → 제안서 지면의 최대 비중을 배분한다. 실제로 본 제안은 Ⅲ.4.2와 Ⅲ.4.3에 각 8장을 배분했다.
- **소밀집이지만 배점 비중이 큰 구간** : `Ⅲ.2.1`(3건) · `Ⅲ.3.1`(1건) · `Ⅲ.2.6`(1건) → 요구사항 건수는 적으나 RFP Ⅳ-1 작성순서 표가 **작성방법 요구(PD-III-*)** 로 직접 지시한 항목이다. 건수가 적다는 이유로 축소하지 않는다.
- **건수 0 구간** : 매핑 건수가 0인 소절은 **요구사항 근거 없이 채워지는 분량**이므로 제안서 구성 단계에서 축소 또는 통합 대상으로 검토했다. 최종 목차에서 건수 0인 level-3 소절은 없다.

### 2.5 요구사항 ID 체계의 착수 후 운영 (PD-IV-3c 연결)

ID 체계는 제안서 제출로 소멸하지 않는다. **착수 후 산출물 검수의 판정 단위**로 그대로 승계하여 다음과 같이 운영한다.

1. **산출물별 요구사항 배정** — 산출물 19종 각각에 대해 "이 산출물이 충족을 증명하는 요구사항 ID 목록"을 착수 2주 내 확정한다. 예: `DL1-1 AI 업무규정` ← `SC1-04`, `SC1-05`, `GM-11`.
2. **검수 시 ID 단위 판정** — 검수 회의에서 산출물 전체를 놓고 "좋다/미흡하다"를 논하지 않고, **배정된 ID를 하나씩 「충족 / 부분충족 / 미충족」으로 판정**한다. 부분충족·미충족 항목만 보완 대상이 되므로 보완 범위가 다투어지지 않는다.
3. **상태 관리** — 추적표의 「반영여부」 열을 `미착수 / 작성중 / 작성완료 / 검토완료`로 갱신하며, 주간 보고 시 카테고리별 진척률을 수치로 보고한다.
4. **변경 관리** — 사업 중 발주처 요구가 추가되거나 법령 개정으로 신규 요구가 발생하면 **새 ID를 부여(예: `ADD-01`)** 하여 추적표에 등재하고, 어느 산출물에 반영할지 함께 결정한다(Ⅲ.2.4 규제 추적 절차와 연결).
5. **최종 인수 시 대조** — 사업 종료 시 추적표 전건이 `검토완료` 상태임을 확인하는 **최종 커버리지 확인서**를 제출한다.

## 3. 제안서용 요약 · 논리 구조

**논리 골격 : [증명 요구] → [분해] → [매핑] → [승계]**

- **[증명 요구]** RFP FM-01은 *"요구하는 모든 사항 기술"* 을 요구 → **선언으로는 증명되지 않는다**
- **[분해]** RFP 전문 → **13개 카테고리 · 257건** ID 부여
  - 분해 원칙 : 한 문장 두 요구는 분리 / 접두어로 성격 구분 / 참고·조건부도 등재
- **[매핑]** 본문 응답 대상 **203건 → 미매핑 0건**
  - 전체 공통 적용 5건(FM-03·04·05·06·12)은 매핑 단위 불성립
  - 제출·평가 실무 49건(AD·EV)은 별도 체크리스트
  - 전수 대조표는 **별첨1**
- **[밀집도 활용]** 최밀집 3개 구간(Ⅲ.4.2 · Ⅲ.4.3 · Ⅲ.4.6)에 지면 최대 배분 / 건수 0 소절 = 0개
- **[승계]** ID = 제안서 도구 ✗ → **검수 판정 단위** ○
  - 산출물별 ID 배정 → **ID 단위 충족/부분충족/미충족 판정** → 보완 범위 무분쟁
  - 신규 요구는 `ADD-` ID 부여 후 등재 → 최종 커버리지 확인서로 종결

## 4. 시각적 표현 방안

### (a) 슬라이드 분할 구조 — 1장

**`전면 표`** — 슬라이드 전면을 커버리지 매트릭스가 차지하고, 좌측 상단에 요약 수치 블록, 하단에 ID 운영 방식 4단계 띠를 배치한다.

### (b) 도해 지시

**커버리지 매트릭스 (히트맵)**
- 세로축 = 13개 카테고리(사업목적 → 계약·수행조건)
- 가로축 = 제안서 대분류 6개(Ⅰ 제안개요 / Ⅱ 제안업체 현황 / Ⅲ 기술부문 / Ⅳ 사업관리 / Ⅴ 지원부문 / Ⅵ 기타) + 「별도 체크리스트」 1열 = 총 7열
- 각 셀에 **매핑 건수를 숫자로 표기**하고 색농도로 밀집도 표현(0건 = 무색, 1~5건 = 연함, 6~15건 = 중간, 16건 이상 = 진함)
- Ⅲ 기술부문 열은 **level-3 소절 단위로 확대한 서브 매트릭스**를 우측에 별도 배치(21개 소절 × 카테고리). 본 제안의 무게중심이 Ⅲ에 있음을 시각적으로 드러낸다
- 「별도 체크리스트」 열의 AD·EV 행에만 값이 있고 나머지가 비어 있는 모습으로 **본문 응답 대상과 실무 요건의 분리**를 표현
- 매트릭스 우측 하단에 **"미매핑 0"** 을 큰 숫자로 배치하고 굵은 테두리로 강조

**좌측 상단 요약 수치 블록 (4칸)**
- `257` 전체 요구사항 / `203` 본문 응답 대상 / `0` 미매핑 / `19` 산출물 종수
- `0` 칸만 강조색 처리

**하단 ID 운영 4단계 띠**
- 가로 4분할 : `① 산출물별 ID 배정(D+14)` → `② ID 단위 검수 판정` → `③ 주간 진척률 보고` → `④ 최종 커버리지 확인서`
- 각 칸 사이에 화살표, ② 칸에 판정 라벨 3종(충족 / 부분충족 / 미충족) 소형 칩 표시

## 5. 인접 절과의 경계 / 인용 근거

### 경계 자기점검

- **Ⅳ.3.3(검수대상 산출물 충족 확인 기준·검증방법)으로 넘긴 것** : 검수 조직 구성, 검수 회의 운영, 검증 방법의 상세. 본 절은 **ID 체계를 검수 판정 단위로 승계한다는 연결**만 기술했고 검수 절차 자체는 기술하지 않았다.
- **Ⅲ.3.3(산출물 체계)으로 넘긴 것** : 산출물 19종의 내역과 제출 시기. 본 절은 산출물을 카테고리 집계의 한 행으로만 다뤘다.
- **Ⅲ.2.4(규제 변화 추적)로 넘긴 것** : 신규 요구 발생 시의 인지·판정·보고 절차. 본 절은 **`ADD-` ID 부여와 추적표 등재**라는 기록 규칙만 기술했다.
- **Ⅵ.1(기타사항)으로 넘긴 것** : 계약·수행조건 38건(`CT-*`)에 대한 수용 의사 표명.
- **별첨1로 넘긴 것** : 요구사항 257건 전수 대조표. 본 절에서 전수 나열하지 않았다.
