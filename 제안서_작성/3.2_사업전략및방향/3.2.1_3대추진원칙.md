# Ⅲ.2.1 3대 추진원칙 : 즉시적용성 · 이원산출 · 규제추적

> **메타** | 요구사항: `PD-III-2a, GM-18, GM-16` | Phase: 전기간 | 예상 분량: 1장

---

## 1. 거버닝 메시지

> **원칙은 구호가 아니라 실패 방지 장치여야 하므로, 본 사업은 「즉시적용성·이원산출·규제추적」 3개 원칙을 각각 하나의 구체적 실패 시나리오에 대응시키고, 원칙마다 그것을 강제하는 산출물 형식과 절차를 지정한다.**

- **서브메시지 1** — **즉시적용성**은 "산출물을 조문·서식·화면 수준으로 만든다"는 형식 규율이다. 보고서 문체로 쓰인 규정은 그대로 시행하지 못하고 다시 쓰게 되므로, 처음부터 **제·개정안 조문 형태**로 작성한다.
- **서브메시지 2** — **이원산출**은 "공통 골격 + 기관별 델타" 구조로 문서를 설계하는 제작 규율이다. 두 벌을 따로 쓰면 개정 때마다 두 배로 틀어진다.
- **서브메시지 3** — **규제추적**은 "확정된 산출물도 다시 연다"는 개정 규율이다. 사업 5개월 동안 규범이 고정되어 있다는 전제를 버리고, 재개정 경로를 미리 뚫어 둔다.

---

## 2. 본문

### 2.1 원칙1. 즉시적용성 — 받는 즉시 시행되는 형태로 만든다

**RFP의 요구** — GM-16은 *"산출물의 수준은 바로 업무에 적용할 수 있어야 함"*, GM-18은 *"단순 요건 충족 수준을 넘어 실제 운영환경에서 즉시 적용 가능한 실행력 있는 거버넌스 체계"* 를 요구한다. 두 요구는 산출물의 **내용**이 아니라 **형식**을 지시한다.

**이 원칙이 없으면 무엇이 실패하는가** — 컨설팅 산출물이 "제언 보고서"로 납품되면 발주처가 이를 내규 문안으로 다시 번역하는 데 별도 기간이 소요된다. Phase1이 2개월인 본 사업에서는 그 번역 기간이 존재하지 않는다. **10월 개시 전에 규정이 시행되지 못한다.**

**구현 장치 3가지**

| 장치 | 내용 | 적용 산출물 |
|---|---|---|
| **조문 형태 산출** | 규정·준칙은 "~할 필요가 있다"가 아니라 **제1조·제2조의 조·항·호 체계와 부칙(시행일)까지 갖춘 제·개정안**으로 작성한다. 기존 내규 개정 시에는 **현행–개정 대비표**를 함께 제출하여 심사 부서가 조문 단위로 검토하도록 한다 | DL1-1, DL1-2 |
| **서식·화면·담당자 내장** | 매뉴얼은 절차 서술로 끝내지 않고 **실제 서식(위험평가서 양식, 게이트 판정서, 승인 요청서), 입력 화면 항목, 수행 직위, 소요일, 판정 기준**을 본문에 포함한다. 매뉴얼을 처음 여는 직원이 그날 업무를 수행하는 상태를 기준으로 완성도를 판정한다 | DL1-6, DL2-4, DL4-2 |
| **사전 실효성 검증** | 완성된 거버넌스를 **10월 3개 과제에 실제로 적용해 보는 시뮬레이션**을 수행하여, 절차가 막히는 지점·판정 기준이 모호한 지점·서식이 부족한 지점을 발견하고 반영한 뒤 확정한다 | DL1-8 |

**판정 방법** — 각 산출물 검수 시 *"이 문서를 받은 담당자가 추가 해석 없이 다음 근무일에 착수하는가"* 를 확인한다. 매뉴얼류는 **해당 업무 미경험자 1인이 매뉴얼만으로 1개 단계를 수행하는 워크스루**를 1회 이상 실시하여 통과 여부를 판정한다.

### 2.2 원칙2. 이원산출 — 공통 골격 위에 기관별 델타를 얹는다

**RFP의 요구** — GM-15는 산출물을 *"은행 및 중앙회(상호금융) 각각 작성 및 검수"* 하도록, GM-09는 *"은행과 상호금융의 업무특성·규모·규제 적용 범위 차이를 반영한 맞춤형 거버넌스 체계"* 를 요구한다.

**이 원칙이 없으면 무엇이 실패하는가** — 두 벌을 독립적으로 작성하면 ① 작성 공수가 두 배가 되어 Phase1 일정이 무너지고 ② 이후 규정 개정 때마다 두 문서가 서로 다른 방향으로 벌어져 **같은 AI서비스에 두 개의 통제 기준이 적용되는 상태**가 된다. 공동 플랫폼을 쓰는 구조에서 이는 운영 사고로 직결된다.

**구현 장치 3가지**

| 장치 | 내용 |
|---|---|
| **문서 3유형 분류** | 착수 2주 내 산출물 19종을 **단일 작성 / 공통 골격 + 기관별 델타 / 완전 분리** 세 유형으로 판정하고 발주처·중앙회와 확정한다. 판정 기준은 "기관별로 값이 달라지는 항목이 조문 단위로 존재하는가"이다 |
| **델타 표기 규약** | 공통 골격 문서에서 기관별로 갈라지는 부분은 **〔은행〕 / 〔상호금융〕 표기 블록**으로 명시하고, 본문 말미에 **「기관별 상이 항목 일람표」** 를 부속한다. 개정 시 이 일람표만 보면 영향 범위가 확인된다 |
| **병렬 검수** | 두 기관 검수를 순차로 돌리지 않는다. **동일 초안을 동시 배포 → 각각 의견 회신 → 합동 조정회의 → 각각 승인**의 4단계로 운영한다 |

**기관별 차이의 세 가지 원천**(GM-09가 명시한 3요소)
- **업무특성** : 은행은 대고객 채널이 직접적이고, 상호금융은 조합을 통한 간접 채널 구조다 → 소비자보호 절차와 민원 에스컬레이션 경로가 갈린다
- **규모** : 상호금융은 조합 단위로 분산되어 있다 → 이용량 계측 차원과 교육 전달 방식이 갈린다
- **규제 적용 범위** : 적용 법령과 감독체계가 다르다 → 책무구조도와 위험등급 임계값이 갈린다

### 2.3 원칙3. 규제추적 — 확정된 산출물도 다시 여는 경로를 미리 뚫는다

**RFP의 요구** — GM-12는 *"법령·가이드라인이 개정되거나 금융당국의 새로운 요구사항이 발생하는 경우 즉시 발주처에 보고하고 산출물에 반영하는 방안"* 을, GM-17은 *"명시된 과제 및 산출물은 예시적 범위"* 이며 추가 확인 시 **제안사가 능동적으로 파악하여 추가 제시**하도록 요구한다.

**이 원칙이 없으면 무엇이 실패하는가** — AI 규범은 현재 개정이 활발한 영역이다. 사업 중 개정이 발생했는데 반영 경로가 없으면, 검수까지 마친 산출물이 **납품 시점에 이미 낡은 문서**가 된다. 그 상태로 10월에 서비스를 열면 규제 리스크는 발주처가 진다.

**구현 장치 3가지**

| 장치 | 내용 |
|---|---|
| **추적 대상 규범 목록 고정** | 착수 2주 내 추적 대상 규범을 목록으로 확정하고 각각에 모니터링 소스와 주기를 배정한다(상세 목록·주기는 Ⅲ.2.4) |
| **영향도 3단계 판정과 보고 시한** | 개정 인지 → 영향도 판정(즉시 반영 / 차기 개정 반영 / 모니터링만) → 발주처 보고까지의 시한을 사전에 고정한다. GM-12가 "즉시 보고"를 명시했으므로 판정 결과와 무관하게 **인지 후 보고를 먼저 수행**한다 |
| **능동 확대 트리거** | 추적 과정에서 RFP 산출물에 대응물이 없는 규제 의무를 발견하면 **추가 과제·산출물로 제안**한다. 이는 사업 중 발견분에 한정하지 않으며, 제안 시점에 이미 발견한 항목을 Ⅲ.4.7에 제시한다 |

### 2.4 세 원칙의 상호 관계

세 원칙은 병렬 나열이 아니라 **하나의 문서 생애를 세 시점에서 규율**한다.

- **만들 때** → 즉시적용성 (형식 규율)
- **두 벌로 나눌 때** → 이원산출 (구조 규율)
- **다시 열 때** → 규제추적 (개정 규율)

따라서 세 원칙은 각각 Ⅲ.2.2(데드라인 역산으로 즉시적용성 확보), Ⅲ.2.3(이원산출의 제작·검수 방법), Ⅲ.2.4(규제추적의 절차)로 이어져 상세화된다.

## 3. 제안서용 요약 · 논리 구조

**논리 골격 : [원칙] → [방지되는 실패] → [구현 장치] → [판정 방법]**

- **원칙1 즉시적용성** (GM-16, GM-18)
  - 방지되는 실패 : *산출물을 내규 문안으로 재번역하는 기간이 Phase1에 없다 → 10월 전 시행 불가*
  - 구현 : **조문 형태 제·개정안 + 현행–개정 대비표** / **서식·화면·직위·소요일·판정기준 내장** / **3개 과제 적용 시뮬레이션 후 확정**
  - 판정 : *"다음 근무일에 착수하는가"* — 미경험자 워크스루 1회 이상
- **원칙2 이원산출** (GM-09, GM-15)
  - 방지되는 실패 : *두 벌 독립 작성 → 공수 2배 + 개정 때마다 벌어짐 → 같은 서비스에 두 기준 적용*
  - 구현 : **문서 3유형 분류(단일 / 공통+델타 / 완전분리)** / **〔은행〕〔상호금융〕 델타 블록 + 상이 항목 일람표** / **동시배포 → 각자회신 → 합동조정 → 각자승인**
  - 차이의 원천 3개 : 업무특성(채널) · 규모(조합 분산) · 규제 적용 범위
- **원칙3 규제추적** (GM-12, GM-17)
  - 방지되는 실패 : *검수 마친 산출물이 납품 시점에 낡은 문서 → 규제 리스크는 발주처 부담*
  - 구현 : **추적 규범 목록 + 모니터링 주기 고정** / **영향도 3단계 판정 + 판정 전 선(先)보고** / **능동 확대 트리거**
- **[상호 관계]** 병렬 ✗ / **하나의 문서 생애를 세 시점에서 규율** ○ — 만들 때 · 나눌 때 · 다시 열 때

## 4. 시각적 표현 방안

### (a) 슬라이드 분할 구조 — 1장

**`3분할 가로 열거`** — 원칙1 | 원칙2 | 원칙3 을 가로 3등분. 각 분할 안에 **[원칙 → 방지되는 실패 → 구현장치] 3단 세로 구조**를 반복 배치한다.

### (b) 도해 지시

**전체 배치**
- 슬라이드 상단에 가로 띠 1개 : *"세 원칙은 하나의 문서 생애를 세 시점에서 규율한다 — 만들 때 · 나눌 때 · 다시 열 때"* 를 배치하여 3분할이 병렬이 아님을 먼저 선언
- 하단 3분할 각 열의 폭은 동일, 열 사이는 세로 구분선

**각 열의 3단 구조**
1. **상단 슬롯(원칙 헤더)** — 원칙 번호 + 명칭 + 근거 요구사항 ID 배지(GM-16·18 / GM-09·15 / GM-12·17). 헤더 배경은 열마다 다른 색상
2. **중단 슬롯(방지되는 실패)** — **적색 경고 아이콘 + 실패 시나리오 1문장**. 세 열 모두 이 슬롯의 배경을 동일한 옅은 적색으로 통일하여 "원칙 = 실패 대응"이라는 메시지를 반복 강조
3. **하단 슬롯(구현 장치)** — 장치 3개를 아이콘 + 짧은 라벨로 세로 나열. 각 장치 우측에 적용 산출물 번호 배지(DL1-1 등)

**연결 화살표**
- 각 열의 하단에서 아래로 화살표를 내려, 슬라이드 최하단의 후속 절 라벨(`Ⅲ.2.2` / `Ⅲ.2.3` / `Ⅲ.2.4`)로 연결한다. 원칙이 곧 다음 세 절의 목차 구조임을 시각화한다

**강조 지점**
- 원칙1 하단 "미경험자 워크스루 1회 이상" 라벨에 별표 배지 — 즉시적용성을 **판정 가능한 기준**으로 만든 유일한 장치이므로

### (c) 표·차트 사양

**표1. 원칙 × 구현장치 × 적용 산출물 대응표** (슬라이드 하단 또는 별지)

| 컬럼 | 내용 |
|---|---|
| 원칙 | 즉시적용성 / 이원산출 / 규제추적 |
| 근거 요구사항 | GM 번호 |
| 방지되는 실패 | 1문장 |
| 구현 장치 | 3개 |
| 적용 산출물 | DL 번호 |
| 판정 방법 | 확인 가능한 기준 |

- 행 예시 1 : `즉시적용성 | GM-16, GM-18 | 재번역 기간이 없어 10월 전 시행 불가 | 조문 형태 산출 / 서식·화면 내장 / 사전 시뮬레이션 | DL1-1, DL1-2, DL1-6, DL2-4, DL4-2, DL1-8 | 미경험자 워크스루 1회 이상 통과`
- 행 예시 2 : `이원산출 | GM-09, GM-15 | 두 벌이 벌어져 같은 서비스에 두 기준 적용 | 3유형 분류 / 델타 블록·상이 항목 일람표 / 병렬 검수 4단계 | 전 산출물 | 상이 항목 일람표 부속 여부`

**표2. 기관별 차이의 원천 3요소** (원칙2 열 확대 시 사용)

| 컬럼 | 내용 |
|---|---|
| 차이 요인 | 업무특성 / 규모 / 규제 적용 범위 |
| 은행 | 특성 서술 |
| 상호금융 | 특성 서술 |
| 갈라지는 산출물 항목 | 조문·항목 단위 |

## 5. 인접 절과의 경계 / 인용 근거

### 경계 자기점검

- **Ⅲ.2.2로 넘긴 것** : Phase1 데드라인 역산 캘린더, 조기 인수 방식, 버퍼 설계. 본 절은 즉시적용성의 **형식 규율**만 선언했다.
- **Ⅲ.2.3으로 넘긴 것** : 이원 산출물의 유형별 판정 결과, 검수 병렬화의 소요일 설계, 이견 조정 절차와 결정 주체. 본 절은 **원칙 선언과 장치 요약**에 그쳤다.

- **Ⅲ.1.2와의 경계** : 산출물 3유형 분류가 **범위에 미치는 영향**은 Ⅲ.1.2가 기술했고, 본 절은 그 분류를 **원칙의 구현 장치**로 참조만 했다.
