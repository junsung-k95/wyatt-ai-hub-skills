# Ⅲ.2.3 전략2) 은행 · 상호금융 이원 산출물 전략

> **메타** | 요구사항: `GM-09, GM-15` | Phase: 전기간 | 예상 분량: 2장

---

## 1. 거버닝 메시지

> **산출물을 두 벌로 만드는 것은 문서를 두 번 쓰는 일이 아니라 「어디까지 같고 어디부터 다른가」를 조문 단위로 판정하는 일이므로, 공통 골격에 기관별 델타를 얹는 단일 원본 구조로 제작하고, 검수는 순차가 아닌 병렬 2레인으로 돌려 Phase1 일정 안에 넣는다.**

- **서브메시지 1** — 산출물 19종을 **단일 작성 / 공통 골격 + 기관별 델타 / 완전 분리** 3유형으로 판정한다. 판정 기준은 감(感)이 아니라 *"기관별로 값이 달라지는 항목이 조문 단위로 존재하는가"* 이다.
- **서브메시지 2** — 은행과 상호금융이 갈라지는 이유는 **업무특성(채널 구조)·규모(조합 분산)·규제 적용 범위** 3개다(GM-09가 명시). 이 3개 원천이 어느 조문을 갈라놓는지를 미리 매핑해 두면 델타 항목이 예측된다.
- **서브메시지 3** — 두 기관 검수를 순차로 돌리면 Phase1이 무너진다. **동시 배포 → 병렬 회신 → 합동 조정회의 → 각각 승인**의 4단계로 운영하며, 이견은 「사실 확인 → 규제 우선 → 보수적 기준 채택 → 발주처 결정」 4단계 규칙으로 종결한다.

> DL4-1을 A형(단일)으로 판정한 것이 이 표에서 가장 중요한 판단이다. 비용 배분은 **양측이 같은 문서에 서명해야 효력이 생기는 합의 문서**이므로, 기관별로 나누어 작성하면 문서 자체가 목적을 잃는다.

### 2.2 은행과 상호금융이 갈라지는 3개 원천 (GM-09)

RFP GM-09는 **업무특성·규모·규제 적용 범위** 세 가지 차이를 반영하도록 명시한다. 각 차이가 어느 조문을 갈라놓는지 미리 매핑한다.

#### 원천 ① 업무특성 — 대고객 채널 구조의 차이

은행은 고객과 직접 계약하고 직접 응대한다. 상호금융은 중앙회가 시스템·상품을 제공하고 **조합이 고객 접점을 담당**하는 2단 구조다. AI서비스의 오류가 고객에게 도달하는 경로가 다르므로 다음 조문이 갈라진다.

| 갈라지는 항목 | 은행 | 상호금융 |
|---|---|---|
| 소비자 고지 주체 | 은행이 직접 고지(AI기본법 제31조제1항) | 중앙회 기준 하에 **조합이 고지**, 고지 문안·게시 방법을 중앙회가 표준화 |
| 민원 접수·에스컬레이션 | 영업점·콜센터 → 소비자보호부 | 조합 → 중앙회 상호금융 소관부 → AI실무협의회 (**1단계 추가**) |
| 이의제기 시 대체 서비스 제공 | 은행 내 비(非)AI 채널 | 조합 창구 대면 처리 |
| 인적 개입(HITL) 수행 직위 | 심사역·담당 팀장 | 조합 담당자 + 중앙회 지원 채널 |

#### 원천 ② 규모 — 조합 단위 분산

상호금융은 다수 조합으로 분산되어 있어 **동일 지침을 전달·교육·점검하는 비용 구조가 다르다.**

| 갈라지는 항목 | 은행 | 상호금융 |
|---|---|---|
| 사용량 계측 차원 | 기관 → 부서 → 지점 | 기관 → 조합 → 조합지점 (**계측 키 1단 추가**) |
| 교육 전달 방식 | 전사 집합·온라인 교육 | 중앙회 → 조합 교육담당자 **전달 교육(Train the Trainer)** |
| 점검 방식 | 내부감사 직접 점검 | 중앙회 표본 점검 + 조합 자체점검 결과 취합 |
| 위험평가 수행 단위 | 서비스 단위 | 서비스 단위(조합 개별 평가 없음) — **평가 결과를 조합에 통지하는 절차 추가** |

#### 원천 ③ 규제 적용 범위 — 적용 법령과 감독체계의 차이

| 갈라지는 항목 | 은행 | 상호금융 |
|---|---|---|
| 책무구조도 근거 | 「금융회사의 지배구조에 관한 법률」에 따른 임원별 책무 배분 | 상호금융 지배구조 체계에 따른 별도 배분 |
| 혁신금융서비스 지위 | **지정 주체** | 위탁 이용 주체 |
| 금융보안원 보안성 검토 | **대응 주체** | 위탁이용 관점 자료 제출 |
| 위험등급 임계값 | AI RMF 기준값(25 / 50 / 75점) 적용 | 동일 항목·배점을 쓰되 **대고객 노출도가 낮은 내부업무형 서비스에 한해 임계값 상향 여지**를 협의 대상으로 둔다 [가정] |
| 감독당국 보고 창구 | 금융감독원 은행 담당 | 상호금융 감독 체계 경유 |

**이 매핑의 활용** — 위 12개 갈라짐 항목이 곧 B형 문서의 **델타 블록 후보 목록**이 된다. 착수 후 현황 진단(Ⅲ.4.1)에서 이 목록을 확정하고, 확정된 목록을 각 문서 말미의 **「기관별 상이 항목 일람표」** 로 부속한다.

### 2.3 제작 방식 — 단일 원본 + 델타 블록

#### 문서 구조 규약

B형 문서는 다음 규약으로 작성한다.

```
제3조 (AI서비스 위험평가)
 ① 위험평가는 합법성·신뢰성·신의성실·보안성 4개 부문 16개 항목으로 실시한다.
 ② 부문별 배점은 합법성 20점, 신뢰성 30점, 신의성실 20점, 보안성 30점으로 한다.
 ③ 잔여위험 점수 합계에 따른 등급 구분은 다음과 같다.
    〔은행〕 25점 미만 저위험 / 25점 이상 50점 미만 중위험 / 50점 이상 고위험
    〔상호금융〕 (동일. 단, 내부업무형 서비스는 별표2의 조정 기준을 적용한다)
 ④ ...
```

- **델타 표기** : 기관별로 갈라지는 부분은 `〔은행〕` / `〔상호금융〕` 블록으로 표기하며, 블록 밖의 본문은 양 기관에 동일 적용된다.
- **일람표 부속** : 문서 말미에 「기관별 상이 항목 일람표」(조문 번호 / 상이 사유 / 은행 값 / 상호금융 값)를 부속한다. **개정 시 이 일람표만 확인하면 영향 범위가 즉시 파악된다.**
- **최종 배포 시 분기 출력** : 검수 완료 후 은행용·상호금융용 배포본을 각각 생성하되, 원본은 하나로 유지하여 이후 개정 시 두 문서가 벌어지는 것을 차단한다.

### 2.4 검수 병렬화 — 4단계 · 소요 15영업일

두 기관 검수를 순차로 돌리면 최소 30영업일이 소요되어 Phase1(60일 ≒ 42영업일) 안에 들어가지 못한다. 병렬 2레인으로 15영업일에 종결한다.

| 단계 | 내용 | 소요 | 은행 레인 | 상호금융 레인 |
|---|---|---|---|---|
| **1. 동시 배포** | 동일 초안을 양 기관에 같은 날 배포. 배포 시 **검토 요청 항목을 지정**(전체 검토가 아니라 델타 후보 조문 중심) | 1일 | 배포 | 배포 |
| **2. 병렬 회신** | 각 기관이 독립적으로 의견 회신. 회신 서식은 **조문 번호 단위**로 고정하여 이후 대조가 가능하도록 함 | 5영업일 | 검토·회신 | 검토·회신 |
| **3. 합동 조정회의** | 제안사가 양 기관 의견을 조문 단위로 대조한 **「의견 대조표」** 를 사전 배포하고, 상충 조문만 회의 안건으로 상정 | 3영업일 (회의 1회 + 정리) | 참석 | 참석 |
| **4. 각각 승인** | 조정 결과를 반영한 최종본을 각 기관이 자기 절차로 승인 | 5영업일 | 승인 | 승인 |
| | **합계** | **15영업일** | | |

**제안사가 3단계에서 하는 일이 병렬화의 핵심이다.** 양 기관 의견을 그대로 전달하면 회의가 조율 회의가 되고 길어진다. 제안사가 **①일치 의견 ②단순 표현 차이 ③실질 상충** 세 부류로 사전 분류하여, ①②는 제안사가 반영하고 **③만 회의 안건으로 올린다.** 통상 상충 조문은 전체의 10% 내외이므로 회의는 1회로 종결된다.

### 2.5 이견 조정 절차와 결정 주체

3단계에서 상충이 해소되지 않을 경우, 다음 4단계 규칙을 순서대로 적용한다. **각 단계에서 결론이 나면 다음 단계로 가지 않는다.**

| 순서 | 판단 규칙 | 적용 예 | 결정 주체 |
|---|---|---|---|
| **1** | **사실 확인 우선** — 이견이 사실 인식 차이에서 비롯되었는지 확인한다. 현황·법령·계약 사실을 대조하면 상당수가 해소된다 | "이 서비스는 대고객이다 / 아니다" | 제안사(사실 제시) |
| **2** | **규제 요건 우선** — 규제가 요구하는 최소선이 있으면 그 선을 따른다. 협의 대상이 아니다 | AI기본법 제31조 고지 의무 | 규제 문언 |
| **3** | **보수적 기준 채택** — 규제선 위의 재량 영역에서 두 기관 기준이 다르면 **더 엄격한 쪽을 공통 기준으로 채택**하고, 완화가 필요한 기관은 별표로 예외를 정의한다 | 위험등급 임계값 | 제안사 권고 + 양 기관 합의 |
| **4** | **발주처 결정** — 1~3으로 해소되지 않으면 **AI실무협의회에 상정**하고, 협의회에서도 미결이면 발주처(수협은행 AX혁신실)의 결정에 따른다. 결정 내용과 사유는 회의록에 남긴다 | 조직 권한 배분 | **발주처** |

**시한** — 1~3단계는 합동 조정회의 당일 종결한다. 4단계 상정이 필요한 항목은 **회의 후 3영업일 내 상정**하고, 미결 상태로 산출물 확정을 미루지 않는다. 미결 조문은 **「보류 조문 목록」** 으로 분리하고 나머지를 먼저 확정한 뒤, 보류분만 추가 개정으로 처리한다.

## 3. 제안서용 요약 · 논리 구조

**논리 골격 : [문제] → [분류] → [원천 매핑] → [제작 규약] → [검수 병렬화] → [이견 종결]**

- **[분류]** 3유형 판정 — **A 단일 5종 / B 공통+델타 8종 / C 완전분리 6종**
  - 판정 질문 : *"기관별로 값이 달라지는 조문이 존재하는가"*
  - 핵심 판단 : **DL4-1 비용 배분 협의서 = A형** ← 양측이 같은 문서에 서명해야 효력 발생
  - 핵심 판단 : **DL2-3 라이프사이클 정의서 = A형** ← 갈라지면 플랫폼이 두 상태값을 갖게 됨
- **[원천 매핑]** GM-09의 3요소 → **갈라지는 조문 12개 사전 식별**
  - 업무특성(채널) → 고지 주체·민원 경로(**1단 추가**)·대체 서비스·HITL 직위
  - 규모(조합 분산) → **계측 키 1단 추가**·전달 교육·표본 점검·평가 결과 통지
  - 규제 범위 → 책무구조도 근거·혁금 지위·보안성 검토 주체·**등급 임계값**·보고 창구
- **[제작 규약]** 단일 원본 + `〔은행〕` `〔상호금융〕` 델타 블록 + **「기관별 상이 항목 일람표」 부속** → 개정 시 영향 범위 즉시 확인
- **[검수 병렬화]** 순차 30영업일 ✗ / **병렬 4단계 15영업일** ○
  - 동시배포(1일) → 병렬회신(5일) → **합동조정(3일)** → 각각승인(5일)
  - 병렬화의 핵심 = 제안사가 의견을 **①일치 ②표현차이 ③실질상충**으로 사전 분류 → **③만 안건 상정**(통상 10% 내외) → 회의 1회 종결
- **[이견 종결]** 4단계 규칙 : **사실 확인 → 규제 우선 → 보수적 기준 채택 → 발주처 결정**
  - 미결 항목은 **「보류 조문 목록」으로 분리**하고 나머지 먼저 확정 → 산출물 확정 지연 차단

## 4. 시각적 표현 방안

### (a) 슬라이드 분할 구조 — 2장

- **1장 : `좌우 2분할 비교` + 중앙 공통 띠** — 왼쪽 은행 ↔ 오른쪽 중앙회·상호금융, 가운데 세로 띠에 공통 골격 배치
- **2장 : `상하 2분할`** — 위 = 병렬 2레인 스윔레인 다이어그램, 아래 = 이견 조정 4단계 계단도

### (b) 도해 지시

**1장 — 이원 산출물 구조도**
- 슬라이드를 세로로 3분할하되 **가운데 띠를 가장 넓게(50%)** 잡는다. 좌우 각 25%. 이 폭 비율 자체가 *"대부분은 공통"* 이라는 메시지를 전달한다
- **가운데 세로 띠(공통 골격)** : 위에서 아래로 A형 산출물 5종을 블록으로 나열(AI윤리원칙 / 라이프사이클 정의서 / 플랫폼 진단서 / 목표 아키텍처 / 비용배분 협의서). 각 블록에 `단일` 배지
- **좌측(은행)·우측(상호금융)** : B형 문서의 델타 블록을 좌우 대칭으로 배치. 각 델타 블록은 가운데 띠에서 뻗어 나온 **가지(branch) 형태**로 그려 원본이 하나임을 표현
- **좌우 최외곽** : C형 산출물 6종을 독립 블록으로 배치(가운데 띠와 연결선 없음). 연결선의 유무가 A·B·C 유형의 차이를 그대로 보여준다
- 좌우 하단에 GM-09의 3개 원천을 아이콘 + 라벨로 표시하고, 각 원천에서 해당 델타 블록으로 **점선 화살표**
- 우측 여백에 범례 : `A 단일 5종 / B 공통+델타 8종 / C 완전분리 6종`

**2장 상단 — 병렬 검수 스윔레인**
- 레인 3개 : 상단 = 은행, 중단 = **제안사(가장 굵게)**, 하단 = 상호금융
- 가로축 = 영업일 1~15
- 1일차에 제안사 레인에서 위·아래로 동시에 뻗는 화살표 2개(동시 배포)
- 2~6일차에 은행·상호금융 레인이 **평행하게 진행**(병렬 회신) — 두 레인의 막대가 같은 구간에 놓이는 것이 이 도해의 핵심
- 7~9일차 제안사 레인에 **의견 대조·3분류 박스**를 크게 배치하고, 여기서 나오는 화살표 3개를 서로 다른 굵기로 : `①일치 → 반영` `②표현차이 → 반영` `③실질상충 → 회의 안건`(가장 굵음, 적색)
- 9일차에 3개 레인이 한 점에 모이는 **합동 조정회의 마름모**
- 10~15일차에 다시 위·아래로 갈라지는 각각 승인 막대
- 하단에 비교 참고 : 순차 방식의 경우를 회색 세선으로 30영업일까지 그려 **길이 차이**를 대비

**2장 하단 — 이견 조정 4단계 계단도**
- 좌→우 상승 계단 4칸 : `①사실 확인` → `②규제 우선` → `③보수적 기준` → `④발주처 결정`
- 각 칸에서 아래로 빠지는 **"여기서 종결" 화살표**를 표시 — 대부분이 앞 단계에서 종결됨을 시각화
- 4번째 칸만 다른 색(발주처 결정)으로 처리하고 `3영업일 내 상정` 배지
- 계단 우측에 **「보류 조문 목록」 아이콘**과 *"미결은 분리, 나머지 먼저 확정"* 라벨

## 5. 인접 절과의 경계 / 인용 근거

### 경계 자기점검

- **Ⅲ.1.2와의 경계** : 산출물 3유형 분류가 **업무범위와 실질 산출 벌수에 미치는 영향**은 Ⅲ.1.2가 개괄했다. 본 절은 **19종 전건의 유형 판정과 제작·검수 방법**을 담당했다. 범위 정의를 반복하지 않았다.
- **Ⅲ.2.1과의 경계** : 이원산출 원칙의 선언과 장치 3개 요약은 Ⅲ.2.1이 했다. 본 절은 그 장치의 **실행 규약**을 기술했다.
- **Ⅲ.4.5로 넘긴 것** : 업무위수탁 부속협약의 조항 구성, 비용 배분 산식, 은행–중앙회 간 AI서비스 운영관리 체계(OBJ-11). 본 절은 **DL4-1을 단일 문서로 판정한 근거**만 기술했고 그 내용은 다루지 않았다.
- **Ⅳ.3(품질보증)으로 넘긴 것** : 검수 조직 구성, 검수 판정 기준의 상세, 산출물 형상관리. 본 절은 **검수의 병렬 진행 구조와 소요일**만 설계했다.
- **Ⅲ.4.1로 넘긴 것** : 델타 후보 12개 항목을 확정하기 위한 현황 진단 방법.

### [가정] 목록

- **[가정]** 산출물 19종의 A/B/C 유형 판정은 제안사 초안이다. 착수 후 2주 내 발주처·중앙회와 확정하며, 확정 결과를 Ⅲ.3.3 산출물 체계표의 「이원화 여부」 열에 반영한다.
- **[가정]** 상호금융의 내부업무형 서비스에 대한 위험등급 임계값 상향 여지를 협의 대상으로 둔 것은 제안사의 제안이며, 규제상 허용 범위 확인 후 결정한다. AI RMF는 배점·임계값의 개별 구성을 허용하나(3.3.1), 완화 방향의 적정성은 발주처 리스크 부서 판단을 따른다.
