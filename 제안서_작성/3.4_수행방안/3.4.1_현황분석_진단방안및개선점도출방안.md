# Ⅲ.4.1 현황 분석 · 진단 방안 및 개선점 도출방안

> **메타** | 요구사항: `PD-III-4a` | Phase: Phase1·Phase2 | 예상 분량: 2장

---

## 1. 거버닝 메시지

> **진단은 "현황을 파악하는 일"이 아니라 "규제 기준선과 대조해 공백을 판정하는 일"이므로, 5개 영역별로 무엇을 열어볼지·누구에게 물을지·무엇과 대조할지를 사전에 확정하고, Phase1에서는 전수 진단 대신 10월 3개 과제 중심의 선별 진단을 먼저 돌려 4주 안에 개선과제를 확정한다.**

- **서브메시지 1** — 진단 대상은 **① 현행 내규 ② 조직·의사결정 체계 ③ AI서비스 인벤토리 ④ 데이터 관리 현황 ⑤ 현행 AI 플랫폼** 5개 영역이다. 각 영역에 **자료요청 목록·인터뷰 대상·진단 문항**을 사전 확정하여 착수 첫날 배포한다.
- **서브메시지 2** — "공백"의 판정 기준은 컨설턴트의 의견이 아니라 **외부 기준선**이다. AI기본법 조항, 금융분야 인공지능 가이드라인 **점검항목 99개**, AI RMF 요구사항, 인공지능 보안 안내서 통제를 기준선으로 삼고 **충족 / 부분충족 / 공백** 3등급으로 판정한다.
- **서브메시지 3** — Phase1 2개월 안에 전수 진단은 불가능하다. **10월 3개 과제와 그에 직접 관련된 내규·보안 영역만 선별 진단(4주)** 하고, 나머지 전수 진단은 Phase2로 이연한다. 축소한 범위와 이연 사유를 진단서에 명시한다.

#### 3등급 판정 정의

| 등급 | 정의 | 판정 근거 요건 | 후속 처리 |
|---|---|---|---|
| **충족** | 대응 내규 조문 또는 운영 절차가 **존재하고 실제로 작동**한다 | ① 근거 조문·절차 문서를 특정할 것 ② **작동 증적 1건 이상**(회의록·결재 이력·점검 기록)을 확인할 것 | 유지 |
| **부분충족** | 근거는 존재하나 **범위·수준·실행 중 하나가 미달**한다 | 미달 사유를 3유형(범위 미달 / 수준 미달 / 미실행) 중 하나로 특정할 것 | **개선과제로 전환** |
| **공백** | 대응 근거가 **존재하지 않는다** | 대조 대상 문서 전체를 확인했음을 기재할 것 | **개선과제로 전환** |
| *(판정 불가)* | 자료 미확보로 판정하지 못함 | **미확보 사실과 그 영향을 진단서에 기재**한다. 추정으로 채우지 않는다 | 자료 확보 후 재판정 |

> **「충족」 판정에 작동 증적을 요구하는 이유** — Ⅲ.3.4 사례 1·3이 보여주듯, 문서에 있으나 작동하지 않는 통제를 충족으로 오판하면 실사 단계에서 드러난다. 갭분석 기법(T1)의 약점을 판정 기준 자체로 보완한다(Ⅲ.3.2의 약점 상쇄 설계).

### 2.3 진단 결과 → 개선과제 도출 → 우선순위화

#### 전환 규칙

**부분충족·공백 판정 항목은 전건 개선과제로 전환한다.** 전환 시 다음 5개 값을 부여한다.

| 값 | 내용 |
|---|---|
| 개선과제 ID | `GAP-nnn` |
| 근거 | 판정된 기준선 조항·점검항목 번호 |
| 미대응 시 리스크 | 규제 위반 / 실사 지적 / 운영 사고 / 정산 불가 중 유형 지정 |
| **배정 과제** | 과제1~4 중 어디서 해결하는가 |
| **배정 산출물** | 어느 DL이 이 과제의 해결을 증명하는가 |

#### 과제 배정 규칙

| 판정 영역 | 배정 과제 | 배정 근거 |
|---|---|---|
| 내규·조직·위험평가·데이터 관리 | **과제1** | 규범과 조직의 문제 |
| 서비스 운영 절차·매뉴얼·당국 대응·증적 | **과제2** | 절차와 실행의 문제 |
| 플랫폼 기능·계측·가드레일 | **과제3** | 시스템의 문제 |
| 비용 배분·정산 근거 | **과제4** | 합의의 문제 |
| 어느 과제에도 배정되지 않는 항목 | **Ⅲ.4.7 추가 제안** | RFP 예시적 범위 밖 → GM-17 능동 확대 대상 |

**마지막 행이 중요하다.** 진단에서 도출된 개선과제 중 RFP의 과제1~4 어디에도 배정되지 않는 항목이 나오면, 그것이 곧 **GM-17이 요구하는 "추가로 확인된 사항"** 이다. 이 항목들은 Ⅲ.4.7의 추가 제안으로 이어진다.

#### 우선순위 부여

개선과제의 우선순위는 Ⅲ.1.3의 4개 축을 그대로 적용한다(재정의하지 않는다).

| 순위 | 판정 |
|---|---|
| **P1 (10월 필수)** | 미대응 시 10월 개시가 불가하거나 금보원 실사 지적으로 이어지는 항목 |
| **P2 (Phase1 내)** | 법정 의무이나 10월 개시와 직접 연결되지 않는 항목 |
| **P3 (Phase2)** | 고도화·확장에 해당하는 항목 |
| **P4 (이관)** | 본 사업 범위를 넘거나 별도 사업이 필요한 항목 → 최종보고서에 이관 대상으로 기재 |

### 2.4 Phase1 압축 진단 — 선별 진단 4주

전수 진단은 5개 영역 × 4개 기준선을 모두 대조하는 작업이며 Phase1 2개월 안에 넣으면 다른 과업이 진행되지 못한다. **범위를 좁혀 4주에 끝낸다.**

| 구분 | Phase1 선별 진단 (D+3 ~ D+30) | Phase2 전수 진단 (D+61 ~ D+80) |
|---|---|---|
| **영역 1 내규** | **10월 3개 과제의 적법성·통제에 직접 관련된 규정만** — 위험관리·정보보호·위탁·책무구조도 | 내규 전체 및 상호금융 내규 |
| **영역 2 조직** | 위원회 신설 가능성·이사회 주기 확인에 한정 | 조직 R&R 전반, 상호금융 협의 채널 |
| **영역 3 서비스** | **10월 3개 과제 집중 진단** + 전체 인벤토리 목록화(판정은 유보) | 전 서비스 판정 |
| **영역 4 데이터** | 3개 과제가 사용하는 데이터에 한정 | AI 전용 데이터 전체 |
| **영역 5 플랫폼** | 보안 통제 구현 여부에 한정(실사 대응 목적) | 실배치 진단 포함 전면 |
| **기준선 적용** | AI기본법 + 보안성 원칙 38개 우선 | 점검항목 99개 전건 |
| **산출** | 선별 진단 결과서, P1 개선과제 목록 | 규범 대조 매트릭스 전건, 개선과제 전체 |

**축소의 명시** — 선별 진단 결과서에 **"이번 진단에서 다루지 않은 영역과 그 사유, Phase2 진단 예정 시점"** 을 명시한다. 축소한 사실을 숨기면 발주처가 진단이 완료된 것으로 오인한다(Ⅲ.3.2의 "no silent caps" 원칙과 동일한 취지).

## 3. 제안서용 요약 · 논리 구조

**논리 골격 : [진단의 정의] → [대상·도구] → [판정 기준] → [과제 전환] → [범위 압축]**

- **[진단의 정의]** "현황 파악" ✗ / **"규제 기준선과 대조한 공백 판정"** ○
- **[대상·도구]** 5개 영역 × [자료요청 목록 / 인터뷰 대상 / 진단 문항 / 대조 기준선]
  - ① 내규(AI 조항 존재 여부) ② 조직(위원회·전담조직 분리) ③ 서비스(고영향·생성형 해당 여부) ④ 데이터(출처·계보·권한) ⑤ 플랫폼(단일 경로·태깅·배포 통제)
  - 자료요청은 **D+1 발송 / D+8 회신**, 항목·기한·담당부서 지정
- **[판정 기준]** 기준선 4종 — **AI기본법·시행령 / 가이드라인 점검항목 99개 / AI RMF / 보안 안내서**
  - 3등급 : **충족 / 부분충족(범위·수준·미실행) / 공백** + *판정 불가*(미확보 사실 기재, 추정 금지)
  - **「충족」에는 작동 증적 1건 이상 요구** ← 문서만 있고 작동 않는 통제의 오판 차단
- **[과제 전환]** 부분충족·공백 = **전건 개선과제 전환**, 5개 값 부여(ID / 근거 / 리스크 유형 / 배정 과제 / 배정 산출물)
  - 배정 규칙 : 규범·조직 → 과제1 / 절차·실행 → 과제2 / 시스템 → 과제3 / 합의 → 과제4
  - **어디에도 배정되지 않는 항목 = GM-17이 말하는 "추가 확인 사항" → Ⅲ.4.7**
  - 우선순위 P1(10월 필수) / P2(Phase1) / P3(Phase2) / P4(이관) — Ⅲ.1.3의 4개 축 그대로 적용
- **[범위 압축]** 전수 진단 불가 → **선별 진단 4주(D+3~D+30)**
  - 3개 과제 + 직접 관련 내규·보안에 한정, 기준선은 AI기본법 + 보안성 38개 우선
  - **축소 범위와 사유·Phase2 예정 시점을 결과서에 명시** ← 완료로 오인되지 않게

## 4. 시각적 표현 방안

### (a) 슬라이드 분할 구조 — 2장

- **1장 : `3분할 가로 열거`** — 「대상 영역」 | 「진단 도구」 | 「판정 기준」 3열 구조
- **2장 : `상하 2분할`** — 위 = 갭 판정 히트맵(5영역 × 3등급) 및 개선과제 전환 흐름, 아래 = Phase1 선별 진단 범위 대비도 + 일정

### (b) 도해 지시

**1장 — 진단 프레임 3분할**
- **좌열「대상 영역」** : 5개 영역을 세로 카드로. 각 카드에 영역 번호·명칭·핵심 질문 1줄
- **중열「진단 도구」** : 각 영역과 같은 높이에 3개 슬롯(`자료요청 n건` / `인터뷰 n인` / `문항 n개`)을 아이콘 + 숫자로 표기. 숫자가 들어가야 도구가 실체로 읽힌다
- **우열「판정 기준」** : 각 영역이 대조하는 기준선을 배지로 표기(`AI기본법 §31~35` / `가이드라인 점검항목 ①~⑧` / `보안 안내서 제3·4·6장` 등)
- 좌 → 중 → 우로 가는 **가로 화살표를 5행 모두에 반복**하여 "영역마다 도구와 기준이 짝지어져 있다"는 구조를 강조
- 우열 오른쪽 끝에 세로 띠로 **기준선 4종 총괄**(AI기본법 / 점검항목 99 / AI RMF / 보안 안내서)을 배치하고, 각 영역에서 이 띠로 연결선

**2장 상단 좌 — 갭 판정 히트맵**
- 세로 = 5개 영역, 가로 = 3등급(충족 / 부분충족 / 공백) + 「판정 불가」 1열
- 셀에 항목 수를 숫자로, 색농도로 밀집 표시
- **「판정 불가」 열을 별도 색(회색 빗금)으로** 처리하여 자료 미확보 구간이 눈에 띄게 한다 — 추정으로 채우지 않았다는 표시
- 표 하단에 *"이 표는 예시 형식이며 실제 값은 진단 후 산출"* 주석

**2장 상단 우 — 개선과제 전환 흐름**
- 좌→우 흐름 : `부분충족·공백 판정` → `GAP-nnn 부여` → `리스크 유형 지정` → `과제 배정` → `우선순위(P1~P4)`
- 「과제 배정」 단계에서 아래로 4개 분기(과제1/2/3/4) + **5번째 분기 「어디에도 배정 불가 → Ⅲ.4.7 추가 제안」**
- 5번째 분기만 다른 색 + 굵은 화살표. GM-17의 능동 확대가 진단에서 자동 발생한다는 것이 이 도해의 핵심 메시지
- 우측 끝에 P1~P4 4단 계단, P1에 「10월 필수」 적색 배지

**2장 하단 — Phase1 선별 진단 범위 대비도**
- 좌우 2분할 : 왼쪽 = **Phase1 선별 진단**(음영 처리된 좁은 영역), 오른쪽 = **Phase2 전수 진단**(전체 영역)
- 동일한 5×4 격자(영역 × 기준선)를 양쪽에 그리고, Phase1에서는 **일부 셀만 채워진 상태**로 표현
- 채워지지 않은 셀 위에 *"Phase2 이연 — 사유 명시"* 라벨
- 하단에 4주 일정 바(D+3~D+30)와 6개 마일스톤 마커

## 5. 인접 절과의 경계 / 인용 근거

### 경계 자기점검

- **Ⅲ.4.2~4.5로 넘긴 것** : 진단으로 도출된 개선과제를 **어떻게 해결하는가**의 전부. 본 절은 **진단 설계**(무엇을 열어보고 무엇과 대조하여 어떻게 판정하는가)에 한정했고, 규정 설계·위험평가체계·라이프사이클·아키텍처·산식은 다루지 않았다.
- **Ⅲ.4.4.1과의 경계** : 본 절 영역 5의 플랫폼 진단은 **보안 통제 구현 여부와 계측 가능성 확인**에 한정한다. **AI 과제를 실제로 배치해 확장성을 측정하는 실배치 진단**(처리량·지연·격리·모델 교체 용이성)은 Ⅲ.4.4.1이 담당한다. 두 진단은 시점(Phase1 vs Phase2)과 목적(실사 대응 vs 확장성 판단)이 다르다.
- **Ⅲ.4.7로 넘긴 것** : 어느 과제에도 배정되지 않은 개선과제의 **추가 과제·산출물 제안 내용**. 본 절은 **전환 규칙**만 정의했다.
- **Ⅲ.1.3으로 넘긴 것** : 우선순위 판단 축 4개. 본 절은 그 축을 **재정의하지 않고** P1~P4 등급 부여에만 적용했다.
- **Ⅲ.3.1·Ⅲ.3.2로 넘긴 것** : 진단이 속한 단계(S1)의 종료조건과 사용 기법(T1 갭분석·T2 규제 매핑·T5 체크리스트 감사)의 장단점. 본 절은 **실제 문항과 자료 목록**을 담당했다.
- **Ⅲ.2.2로 넘긴 것** : D+n 일정의 산정 근거. 본 절의 진단 일정은 그 캘린더에 연동된 값이다.

### [가정] 목록

- **[가정]** 자료요청 목록의 회신 기한(D+8)은 제안사 계상치이며, 착수보고 시 발주처와 확정한다. 회신율이 50% 미만이면 Ⅲ.2.5의 위험 R-07 대응 절차를 적용한다.
- **[가정]** 10월 출시 3개 과제의 서비스 정의서·아키텍처·데이터 흐름도를 D+3까지 제공받는 것을 전제로 선별 진단 일정을 설계했다. 제공이 지연되면 진단 착수일과 후속 마일스톤을 동일 일수만큼 순연하고 즉시 보고한다.
- **[가정]** 인터뷰 대상 인원 수(영역당 2~3인)는 제안사 계상치이며, 실제 조직 구성 확인 후 조정한다. 실명이 아닌 부서·직위 수준으로 지정한다.
- **[가정]** 상호금융(중앙회) 측 자료 제공 창구를 단일 창구로 전제했다. 조합 단위 자료가 필요한 항목(영역 3·4)은 중앙회를 통해 표본 자료를 확보한다.
- **[가정]** 「충족」 판정에 작동 증적 1건 이상을 요구하는 기준은 제안사가 설정한 것이다. 증적이 존재하나 제출이 제한되는 경우(감사 자료 등) 담당자 확인으로 대체하고 그 사실을 판정 근거에 기재한다.
- **[가정]** Phase1 선별 진단의 축소 범위(내규 일부·조직 일부·데이터 일부·플랫폼 보안 한정)는 제안사 판단이다. 착수 워크숍에서 발주처와 확정하며, 확정 결과를 선별 진단 결과서에 명시한다.
