# Ⅲ.4.5 [과제4] 공동 AI 플랫폼 비용 배분 체계 합리화

> **메타** | 요구사항: `PD-III-4b, SC4-01~SC4-04, OBJ-02, GM-07, OBJ-11` (8건) | Phase: Phase1·전기간 | 예상 분량: 5장

---

## 1. 거버닝 메시지

> **비용 배분은 논리적으로 옳은 산식을 찾는 문제가 아니라 양 기관이 서명할 수 있는 산식을 만드는 문제이므로, 단일안 대신 대안 3안과 각 안의 기관별 시산 금액을 함께 제시해 논의를 「찬반」에서 「선택」으로 바꾸고, 모든 변수를 실제로 계측되는 항목만으로 구성하여 합의 직후 정산이 실행되게 한다.**

- **서브메시지 1** — 개발비는 **공통 기반부 · 기관 전용부**로 먼저 분해한다. 전용부는 수익자에게 직접 귀속시키고, 공통 기반부만 배분 대상으로 남기면 협의 범위가 좁아진다.
- **서브메시지 2** — 이용료는 **공통비(항상 가동되는 공동 존 인프라)** 와 **변동비(사용량 비례)** 로 분리한다. 변동비는 실계측으로 직접 귀속되므로 다툴 여지가 없고, 협의 대상은 공통비 배분 기준 하나로 좁아진다.
- **서브메시지 3** — **산식의 모든 변수는 계측 원천과 1:1로 매핑**한다. 계측되지 않는 변수는 설계 단계에서 제거하거나 대안 배부키로 교체하고, 대안 배부키를 쓰는 항목은 협의서 별표에 명시한다(Ⅲ.3.4 사례 6).

## 2. 본문

### 4.5.1 AI서비스 개발비용 배분 기준 및 정산방안

**담당 요구사항 : SC4-01, SC4-02**

#### (1) 개발비 3분해 — 배분 대상을 먼저 좁힌다

개발비 총액을 먼저 세 갈래로 나눈다. **배분을 다투기 전에 다툴 필요가 없는 부분을 걷어내는 것**이 협의 시간을 줄이는 가장 효과적인 조치다.

| 구분 | 정의 | 귀속 |
|---|---|---|
| **C_base 공통 기반부** | 양 기관이 공통으로 사용하는 기능·인프라의 개발비(게이트웨이, 정책 엔진, 공통 모델 서빙, 관측 체계, 공통 데이터 파이프라인) | **배분 대상** |
| **C_bank 은행 전용부** | 은행의 요구로만 개발된 기능 | 은행 100% 직접 귀속 |
| **C_mg 상호금융 전용부** | 상호금융의 요구로만 개발된 기능 | 중앙회 100% 직접 귀속 |

**분해 판정 기준** — 요건 정의서의 요구사항 항목 단위로 판정한다. `양 기관이 모두 사용하는가?` → YES면 C_base, NO면 해당 기관 전용부. 판정 결과는 **요구사항 단위 분해표**로 남겨 사후 이견을 차단한다.

#### (2) C_base 배분 방식 — 대안 5안 비교 (SC4-01)

| 안 | 산정 방식 | 언제 타당한가 | 장점 | 단점 | 수협 적용 시 쟁점 |
|---|---|---|---|---|---|
| **A. 균등분담** | 50 : 50 | 사용량 예측이 불가능하고 양측 지위가 대등할 때 | 산정이 단순, 협의가 빠름 | 실사용 격차가 크면 한쪽이 불공정을 주장 | 은행 사용량이 상호금융보다 클 것으로 예상되면 은행이 수용 곤란 |
| **B. 예상 사용량 기준** | 개시 후 12개월 예상 사용량 점유율 | 사용량 예측이 가능하고 사용량이 효익에 비례할 때 | 원인–결과가 명확, 설득력 높음 | **예측치의 신뢰성이 쟁점**이 됨. 예측이 빗나가면 재협의 | 개시 전이라 예측 근거가 약함 |
| **C. 수익·효익 기준** | 서비스로 창출되는 수익·비용절감 추정치 비율 | 효익 산정이 가능한 대고객 수익형 서비스 | 경제적 실질에 부합 | 효익 추정의 자의성, 내부 업무형 서비스에는 적용 곤란 | 10월 3개 과제의 효익 산정 근거 미확보 |
| **D. 자산·규모 기준** | 총자산·영업규모 비율 | 사용량과 무관하게 부담 능력으로 나눌 때 | 객관적 외부 지표, 다툼 적음 | AI 사용량과 무관 → **적게 쓰는 쪽이 과다 부담** | 상호금융 규모 지표 선택(자산 / 조합 수 / 이용자 수)에서 이견 소지 |
| **E. 혼합 (기본지분 + 사용량 조정)** | `기본지분 α × 균등 + (1−α) × 예상 사용량 점유율`, 개시 후 **실사용량으로 사후 정산** | 사용량 예측 신뢰도가 중간이고, 공동 인프라의 **가용성 자체에 가치**가 있을 때 | ① 균등의 안정성과 사용량의 공정성을 결합 ② **사후 정산 조항으로 예측 오차를 흡수** ③ 협의를 α 하나로 좁힘 | 산식이 상대적으로 복잡, α 결정에 근거 필요 | α 값과 사후 정산 상한을 협의해야 함 |

#### (3) 권고안 : E 혼합 방식

**산식**

```
r_bank = α × 0.5 + (1 − α) × u_bank
r_mg   = 1 − r_bank

  α      : 기본지분 가중치 (권고 0.5)
  u_bank : 개시 후 12개월 은행 예상 사용량 점유율 (토큰 수 기준)

개발비 부담액
  은행    = C_bank + C_base × r_bank
  중앙회  = C_mg   + C_base × r_mg
```

**권고 근거 3가지**
1. **공동 존 인프라는 쓰지 않아도 유지된다.** 게이트웨이·정책 엔진·관측 체계는 한쪽이 적게 써도 동일하게 구축·운영되므로, 100% 사용량 비례(B안)는 가용성의 가치를 반영하지 못한다. 기본지분 α가 이 부분을 담는다.
2. **예측치의 신뢰성 문제를 사후 정산으로 흡수한다.** B안의 최대 약점인 "예측이 틀리면?"에 대해, 개시 후 12개월 실사용량으로 재계산하여 차액을 정산하는 조항을 둔다.
3. **협의 변수를 α 하나로 압축한다.** 다른 안은 배분 방식 자체를 다투게 되지만, E안은 *"α를 얼마로 할 것인가"* 라는 **단일 숫자 협의**로 바뀐다.

**사후 정산 조항**

| 항목 | 내용 |
|---|---|
| 정산 시점 | 서비스 개시 후 **12개월 경과 시점** |
| 재계산 방식 | `u_bank`를 **실사용량 점유율**로 교체하여 `r_bank` 재산정 |
| **조정 상한** | 최초 산정 대비 **±10%p 이내**로 제한. 상한 초과 시 상한까지만 조정하고 잔여는 다음 정산으로 이월 |
| 차액 처리 | 과부담 기관에 환급, 과소부담 기관이 추가 납부 |
| 재정산 주기 | 최초 1회 후, 사용량 점유율이 **직전 정산 대비 10%p 이상 변동**하면 추가 정산 |

#### (4) 단독·후속 개발 시 청구 기준 (SC4-02)

| 유형 | 정의 | 청구 기준 |
|---|---|---|
| **단독 개발** | 한 기관만 사용할 기능을 그 기관의 요구로 개발 | **요구 기관 100% 부담**. 원가 산정 범위 = 직접 인건비 + 외부 용역비 + 전용 인프라 증분 |
| **후속 공동 개발** | 기존 공동 기능의 고도화를 양측이 함께 요구 | C_base와 동일한 배분(당시 `r` 재적용) |
| **단독 개발 후 타 기관 전용(轉用)** | 한 기관이 단독 부담해 개발한 기능을 이후 다른 기관이 사용 | **정산 조정** — 아래 산식 적용 |
| **공동 자산 활용 단독 개발** | 단독 개발이지만 기존 공동 기반(게이트웨이·파이프라인 등)을 활용 | 단독 부담. 단 **공동 기반 활용분은 추가 청구하지 않음**(이미 C_base로 부담했으므로 이중 부담 방지) |

**전용(轉用) 시 정산 조정 산식**

```
전용 대가 = 원 개발비 × 잔존가치율 × 신규 사용 기관의 배분율 r'

  잔존가치율 = (내용연수 − 경과연수) ÷ 내용연수   (내용연수 권고 5년)
  r'         = 전용 시점의 사용량 점유율 기준 배분율
```

- 전용 대가는 원 부담 기관에 지급한다.
- **내용연수 5년**은 소프트웨어 자산의 통상적 상각 기간을 준용한 값이며, 발주처 회계 기준에 따라 조정한다.

**원가 산정 범위 (공통)**

| 포함 | 제외 |
|---|---|
| 직접 인건비(투입 M/M × 등급별 단가) | 기관 내부 인건비 중 일반 관리 성격 |
| 외부 용역·라이선스 비용 | 기존 자산의 감가상각 |
| 전용 하드웨어·인프라 증분 | 공동 기반의 재청구 |
| 개발 기간 중 발생한 클라우드 자원 비용 | 사업 관리 간접비(별도 합의 시 포함) |

#### (5) 정산 시점·절차·증빙

| 단계 | 내용 | 시점 |
|---|---|---|
| ① 요구사항 분해 확정 | C_base / C_bank / C_mg 판정표를 양측이 확인·서명 | 개발 착수 전 |
| ② 배분율 산정 | α 및 `u_bank` 확정, `r` 산출 | 개발 착수 전 |
| ③ 개발 완료·검수 | 실제 발생 원가 정리, 증빙 첨부 | 개발 완료 시 |
| ④ 정산 청구 | 기관별 부담액 청구서 발행 | 검수 후 30일 내 |
| ⑤ 지급 | 청구서 접수 후 지급 | 청구 후 30일 내 |
| ⑥ 사후 정산 | 개시 12개월 후 실사용량으로 재계산, 차액 정산 | 개시 + 12개월 |

**증빙** — 투입 인력 명세(등급·기간), 외부 계약서·세금계산서, 클라우드 사용 내역, 요구사항 분해 판정표.

### 4.5.2 AI서비스 이용비용 배분 기준 및 과금체계

**담당 요구사항 : SC4-03, SC4-04, OBJ-02**

#### (1) 계측 단위 정의 — 무엇을 세는가 (SC4-03)

| 계측 단위 | 정의 | 계측 원천 | 비용 성격 |
|---|---|---|---|
| **호출 수** | 게이트웨이를 통과한 요청 건수 | 게이트웨이 로그(R5) | 변동비 |
| **토큰 수** | 입력 토큰 + 출력 토큰 (가중치 분리 적용) | 게이트웨이 로그 | 변동비 |
| **GPU 시간** | 모델 서빙·학습에 사용된 가속기 점유 시간 | 클라우드 청구 + 서빙 메트릭 | 변동비 |
| **스토리지 GB·월** | 데이터·모델·로그 저장 용량 | 클라우드 청구 | 변동비 |
| **전용 인스턴스 시간** | 기관 전용으로 상시 점유하는 인스턴스 | 클라우드 청구 | **직접비** |
| **공동 존 기본 인프라** | 게이트웨이·정책 엔진·모델 레지스트리·관측 인프라의 상시 가동 자원 | 클라우드 청구(공동 존 계정·태그) | **공통비** |

> **주 계측 단위는 토큰 수**로 한다. 호출 수는 요청 크기 차이를 반영하지 못하고, GPU 시간은 공유 서빙 환경에서 기관별 귀속이 어렵다. 다만 **비생성형 모델(판별형)은 호출 수**를 사용하며, 두 단위를 **단가 환산표**로 통합한다.

#### (2) 공통비 / 변동비 / 직접비 분리

```
월 이용료 총액  T = F(공통비) + V(변동비) + D(직접비)

  F : 공동 존 기본 인프라 비용 — 사용량과 무관하게 발생
  V : 사용량 비례 비용 — 토큰·호출·GPU·스토리지
  D : 기관 전용 자원 비용 — 귀속 명확
```

이 3분 구조는 **과제3의 공동 존 아키텍처(4.4.2)와 1:1로 대응**한다. 아키텍처의 자원 배치가 곧 비용 구조를 결정하므로, 두 절의 구분이 어긋나면 계측이 성립하지 않는다.

#### (3) 기관 간 배분 산식

```
[변동비 V]  실계측 직접 귀속
   V_bank = Σ (은행 태그가 부착된 사용량 × 자원별 단가)
   V_mg   = Σ (상호금융 태그가 부착된 사용량 × 자원별 단가)

[직접비 D]  전용 자원 보유 기관에 전액 귀속

[공통비 F]  사용량 점유율 기준 배분
   s_bank = 직전 3개월 이동평균 토큰 점유율(은행)
   F_bank = F × s_bank
   F_mg   = F × (1 − s_bank)

[기관별 월 부담액]
   은행    = V_bank + D_bank + F_bank
   중앙회  = V_mg   + D_mg   + F_mg
```

**공통비 배분에 「직전 3개월 이동평균」을 쓰는 이유** — 단월 점유율을 쓰면 특정 월의 이벤트성 사용 증가가 그대로 부담으로 전이되어 예측 가능성이 떨어진다. 3개월 이동평균은 변동을 완화하면서도 추세를 반영한다.

#### (4) 부서·지점·조합 단위 실비 정산 (SC4-04)

**기관 내부 배부 절차**

```
[1단계] 기관별 총 부담액 산출 (위 산식)
   ↓
[2단계] 계측 가능분 직접 배부
   부서/지점/조합별 = 해당 조직 태그 사용량 × 자원별 단가 + 공통비 배부액
   ↓
[3단계] 계측 불가분 대안 배부
   대안 배부키 적용 (아래 표)
   ↓
[4단계] 검산 — Σ(조직별 배부액) = 기관 총 부담액
```

**계측 차원과 상호금융의 추가 계층**

| 기관 | 계측 계층 |
|---|---|
| 은행 | 기관 → **본부 부서 / 영업점** → 서비스 → 모델 |
| 상호금융 | 기관 → **조합 → 조합지점** → 서비스 → 모델 (**1단 더 깊다**) |

**대안 배부키** — 계측이 불가능한 항목에 적용한다. 적용 항목은 **협의서 별표에 명시**한다.

| 계측 불가 항목 | 대안 배부키 | 근거 |
|---|---|---|
| 조직 태그가 부착되지 않은 공용 조회 트래픽 | 해당 서비스의 **조직별 이용자 수** 비율 | 이용자 수가 사용량의 대리 지표 |
| 배치 처리(야간 일괄 추론) | 처리 **대상 건수의 조직별 비율** | 처리 건수가 직접 원인 |
| 공동 존 기본 인프라의 기관 내 배부 | **조직별 계측 사용량 비율** | 사용량 비례 원칙 유지 |
| 초기 도입 기간(태그 체계 미적용 구간) | **조직별 인원수** | 임시 적용, 태그 적용 즉시 전환 |

#### (5) 산식 검증 — 숫자 예시 1개월치

**전제 (가상 수치)**

| 항목 | 값 |
|---|---|
| 월 공통비 F | 40,000천원 |
| 월 변동비 V | 60,000천원 |
| 월 직접비 D | 은행 8,000천원 / 상호금융 0 |
| 당월 토큰 사용량 | 은행 700만 토큰 / 상호금융 300만 토큰 |
| 직전 3개월 이동평균 토큰 점유율 | 은행 **68%** / 상호금융 32% |

**계산**

| 구분 | 산식 | 은행 | 상호금융 |
|---|---|---|---|
| 변동비 V | 60,000 × 당월 실사용 점유율(70 : 30) | **42,000** | **18,000** |
| 직접비 D | 전용 자원 보유 기관 귀속 | **8,000** | **0** |
| 공통비 F | 40,000 × 이동평균 점유율(68 : 32) | **27,200** | **12,800** |
| **월 부담액** | V + D + F | **77,200천원** | **30,800천원** |
| 검산 | 77,200 + 30,800 = 108,000 = F + V + D | ✓ | |

**상호금융 내부 배부 예시** (30,800천원)

| 조합 | 계측 토큰 | 계측 배부액 | 미계측분 배부(5%, 이용자 수 키) | 합계 |
|---|---|---|---|---|
| A조합 | 120만 (40%) | 11,704 | 616 | **12,320** |
| B조합 | 105만 (35%) | 10,241 | 539 | **10,780** |
| C조합 | 75만 (25%) | 7,315 | 385 | **7,700** |
| 계 | 300만 | 29,260 | 1,540 | **30,800** ✓ |

> 이 시산은 **산식이 실제로 계산되는지를 검증**하기 위한 것이다. 착수 후 실제 원가와 계측 데이터로 재산정하며, 협의 시에는 **대안 3안 각각에 대해 같은 형식의 시산표를 함께 제시**한다(Ⅲ.3.4 사례 4의 사전 조치).

#### (6) 월별 정산 프로세스와 이의제기

| 단계 | 내용 | 수행 | 시한 |
|---|---|---|---|
| ① 계측 마감 | 전월 사용량 집계 마감, 결측 항목 확인 | 플랫폼 운영 | 익월 **3영업일** |
| ② 원가 확정 | 클라우드 청구서 수령 및 F·V·D 구분 확정 | AX혁신실 + 재무 | 익월 **7영업일** |
| ③ 배분 계산 | 산식 적용, 기관별·조직별 배부액 산출 | AX혁신실 | 익월 **10영업일** |
| ④ 명세 송부 | 기관별 정산 명세서 송부(계측 내역·산식 적용 근거 포함) | AX혁신실 → 중앙회 | 익월 **12영업일** |

**이의제기 처리 규칙**
- 이의는 **계측 수치 / 산식 적용 / 배부키 적용** 3유형으로 분류하여 접수한다.
- **계측 수치 이의**는 원자료(게이트웨이 로그·클라우드 청구) 대조로 판정하며, 판정 결과는 다툴 수 없다.
- **산식·배부키 이의**는 협의서 조항 해석 문제이므로 **운영관리 협의체**에 상정한다.
- 이의 미제기 시 **명세 수령 후 10영업일 경과로 확정**된다.
- 조정이 확정되면 **다음 달 정산에 반영**하고 소급 재청구하지 않는다(정산 실무 부담 완화).

## 3. 제안서용 요약 · 논리 구조

**논리 골격 : [분해] → [대안 비교] → [권고 산식] → [계측 정합] → [검증] → [합의 구조]**

- **[분해]** 다투기 전에 **다툴 필요 없는 부분을 걷어낸다**
  - 개발비 : **C_base(배분 대상) / C_bank / C_mg(직접 귀속)** — 요구사항 항목 단위 판정표
  - 이용료 : **F 공통비 / V 변동비 / D 직접비** — V·D는 실계측 직접 귀속 → **협의 대상은 F 배분 기준 하나**
  - 이 3분 구조가 **과제3 공동 존 아키텍처와 1:1 대응**
- **[대안 비교]** C_base 배분 **5안 × [언제 타당·장점·단점·수협 쟁점]**
  - A 균등 / B 예상 사용량 / C 수익·효익 / D 자산규모 / **E 혼합**
- **[권고 산식]** **E 혼합** — `r_bank = α × 0.5 + (1−α) × u_bank`, α 권고 **0.5**
  - 근거 3 : **공동 인프라는 안 써도 유지됨**(가용성 가치) / 예측 오차를 **사후 정산으로 흡수** / 협의를 **α 단일 숫자로 압축**
  - 사후 정산 : 개시 **12개월** 후 실사용량 재계산, **조정 상한 ±10%p**, 이후 10%p 이상 변동 시 추가 정산
  - 단독·후속 4유형, **전용(轉用) 대가 = 원 개발비 × 잔존가치율 × r'**(내용연수 5년)
  - **공동 기반 활용분 이중 청구 금지**
- **[이용료 산식]** V 실계측 직접 귀속 / D 전용 기관 귀속 / **F = 직전 3개월 이동평균 점유율 배분**(단월 변동 완화)
  - 주 계측 단위 = **토큰 수**(호출 수는 크기 미반영, GPU는 공유 환경 귀속 곤란), 판별형은 호출 수 + 단가 환산표
  - 내부 배부 4단계, **상호금융은 조합 → 조합지점 1단 추가**
  - 대안 배부키 4종 → **협의서 별표 명시**
- **[검증]** 1개월치 시산 — F 40,000 / V 60,000 / D 8,000
  - 결과 : **은행 77,200천원 / 상호금융 30,800천원**, 검산 108,000 ✓
  - 상호금융 내부 3개 조합 배부까지 전개, 미계측 5%는 이용자 수 키
  - **협의 시 대안 3안 각각에 같은 형식의 시산표 동시 제시**
- **[합의 구조]** 부속협약 **7장 30조 + 별표 5종**, 정산 산식은 **별표2·3·4로 분리**하여 개정 부담 완화
  - 협의 일정 D+7 협의체 → D+24 3안+시산 → D+38 권고안 → **D+55 서명**
  - 쟁점 **사전 3분해**(공동이용 범위 / 배분 기준 / 정산 주기), D+50 미성립 시 **부분 합의 + 잠정 비율**
  - **운영관리(OBJ-11) = 정산과 별개** — 8개 사안 × [결정 주체·협의 요건·통보 시한]
    - 긴급 장애·Kill switch = **은행 단독 결정 후 사후 통보**(지연이 피해를 키움)
    - 사양 변경·중단·정산 기준 변경 = **양측 합의**

## 4. 시각적 표현 방안

### (a) 슬라이드 분할 구조 — 5장

| 장 | 내용 | 분할 패턴 |
|---|---|---|
| **1** | 비용 구조 분해도 + 배분 대상 좁히기 | `중앙 다이어그램 + 주변 설명` |
| **2** | 개발비 배분 5안 비교 및 권고 산식 | `전면 표` |
| **3** | 이용료 산식 + 계측 정합 | `상하 2분할` |
| **4** | 숫자 예시 시산표 | `전면 표` |
| **5** | 부속협약 및 운영관리 체계 | `좌우 2분할 비교` |

### (b) 도해 지시

**1장 — 비용 구조 분해도**
- 중앙에 **「총비용」 블록**을 두고 아래로 트리 전개
- 1단 분기 : `개발비` / `이용료`
- 개발비 하위 3분기 : **C_base(배분 대상, 강조색)** / C_bank(직접 귀속, 회색) / C_mg(직접 귀속, 회색)
- 이용료 하위 3분기 : **F 공통비(배분 대상, 강조색)** / V 변동비(직접 귀속, 회색) / D 직접비(직접 귀속, 회색)
- **강조색 블록은 2개(C_base·F)뿐**이라는 사실이 시각적으로 드러나야 한다. 이 슬라이드의 메시지는 *"협의 대상은 두 개로 좁혀진다"* 이다
- 회색 블록에는 **「다툴 여지 없음 — 실계측/직접 귀속」** 라벨
- 우측에 과제3 공동 존 아키텍처 3영역(공동 존 / 전용 / 가변)을 작게 그리고, 비용 3분 구조와 **점선으로 1:1 연결**

**2장 — 개발비 5안 비교표**
- 5열 × 5행(산정 방식 / 언제 타당 / 장점 / 단점 / 수협 쟁점)
- **E안 열 전체를 강조 배경 + 「권고」 배지**
- 표 하단에 권고 산식을 수식 블록으로 크게 : `r_bank = α × 0.5 + (1−α) × u_bank`
- 수식 아래에 **α 슬라이더 도해** — α를 0에서 1로 움직였을 때 은행 부담율이 어떻게 변하는지를 가로 막대로 표현하고, 권고값 0.5 지점에 마커. *"협의는 이 하나의 숫자에 대해 이루어진다"* 라벨
- 우측에 사후 정산 조항을 카드로(정산 시점 / 재계산 / **±10%p 상한** / 차액 처리)

**3장 — 이용료 산식 및 계측 정합**
- 상단 : 산식 블록 3개를 좌→우로 `V 실계측` → `D 직접 귀속` → `F 이동평균 배분`
- 각 블록 아래에 **계측 원천 아이콘**(게이트웨이 로그 / 클라우드 청구)을 배치하고 화살표로 연결
- **F 블록만 다른 색** — 유일한 협의 대상이므로
- 하단 : 계측 계층 트리 좌우 대비 — 왼쪽 은행 `기관 → 부서/영업점 → 서비스 → 모델`, 오른쪽 상호금융 `기관 → 조합 → 조합지점 → 서비스 → 모델`
- **상호금융 트리가 한 단 더 깊은 모습**을 굵은 테두리로 강조하고 *"계측 키 1단 추가"* 라벨
- 하단 우측에 대안 배부키 4종을 표로, 각각에 **「협의서 별표 명시」 배지**

**4장 — 시산표**
- 전면에 계산표. 왼쪽에 산식, 오른쪽에 은행·상호금융 2열
- 각 행의 계산 과정을 **화살표로 연결**하여 값이 어떻게 도출되는지 추적되게 한다
- 최하단 검산 행에 **✓ 마커**와 `108,000 = F + V + D` 표기
- 우측에 상호금융 내부 배부 표(3개 조합), 미계측 5% 배부 열을 다른 색으로
- 표 하단 주석 : *"협의 시에는 대안 3안 각각에 대해 같은 형식의 시산표를 함께 제시"* 를 굵게 — 이것이 Ⅲ.3.4 사례 4의 교훈이므로

**5장 — 부속협약 + 운영관리**
- 좌우 2분할
- **왼쪽 「부속협약」** : 7장 30조 목차를 세로 목록으로. **제3장(비용 부담 및 정산)** 블록을 강조하고, 거기서 오른쪽으로 화살표를 뻗어 **별표 5종 아이콘**에 연결. *"산식은 별표로 분리 → 개정 시 협약 본문 미개정"* 주석
- 좌하단에 협의 일정 타임라인(D+7 → D+24 → D+38 → **D+55 서명**), D+50 지점에 **분기 화살표**로 「부분 합의 + 잠정 비율」 대체 경로 표시
- **오른쪽 「운영관리 체계」** : 8개 사안을 세로 배치하고, 각 사안을 **결정 주체별 3색**으로 구분 — `은행 단독`(적) / `은행 결정 + 통보`(황) / `양측 합의`(청)
- 색 분포가 위(긴급)에서 아래(구조적)로 갈수록 적→황→청으로 변하는 그라데이션이 보이게 배치. *"급할수록 단독, 구조적일수록 합의"* 라는 원칙을 색으로 전달
- 각 사안 우측에 **통보 시한 배지**(1시간 / 1영업일 / 10영업일 / 60일)

### (c) 표·차트 사양

**표1. 개발비 배분 대안 비교표** (2장 주력)

| 컬럼 | 안 / 산정 방식 / 언제 타당한가 / 장점 / 단점 / 수협 적용 시 쟁점 |
- 행 예시 1 : `B. 예상 사용량 기준 | 개시 후 12개월 예상 사용량 점유율 | 사용량 예측이 가능하고 사용량이 효익에 비례할 때 | 원인–결과 명확, 설득력 높음 | 예측치의 신뢰성이 쟁점, 예측이 빗나가면 재협의 | 개시 전이라 예측 근거가 약함`
- 행 예시 2 : `E. 혼합(권고) | α × 균등 + (1−α) × 예상 사용량 점유율, 개시 후 실사용량 사후 정산 | 예측 신뢰도가 중간이고 공동 인프라의 가용성 자체에 가치가 있을 때 | 균등의 안정성 + 사용량의 공정성 결합, 사후 정산으로 예측 오차 흡수, 협의를 α 하나로 압축 | 산식이 상대적으로 복잡, α 결정 근거 필요 | α 값과 사후 정산 상한 협의 필요`

**표2. 계측 단위 정의표** (3장)

| 컬럼 | 계측 단위 / 정의 / 계측 원천 / 비용 성격 / 결측 시 대안 배부키 |
- 행 예시 1 : `토큰 수 | 입력 토큰 + 출력 토큰(가중치 분리 적용) | 게이트웨이 로그(R5) | 변동비 | 해당 없음(주 계측 단위)`
- 행 예시 2 : `공동 존 기본 인프라 | 게이트웨이·정책엔진·모델 레지스트리·관측 인프라의 상시 가동 자원 | 클라우드 청구(공동 존 계정·태그) | 공통비 | 조직별 계측 사용량 비율`

**표3. 월 정산 시산표** (4장 주력)

| 컬럼 | 구분 / 산식 / 은행 / 상호금융 |
- 행 예시 1 : `변동비 V | 60,000 × 당월 실사용 점유율(70:30) | 42,000 | 18,000`
- 행 예시 2 : `공통비 F | 40,000 × 직전 3개월 이동평균 점유율(68:32) | 27,200 | 12,800`

**표4. 운영관리 결정 체계표** (5장)

| 컬럼 | 사안 / 결정 주체 / 협의 요건 / 통보 시한 |
- 행 예시 1 : `긴급 장애 대응 | 은행 단독 결정 후 사후 통보 | 사전 협의 불요(지연이 피해를 키움) | 조치 후 1시간 내 통보, 1영업일 내 원인·조치 보고`
- 행 예시 2 : `서비스 사양 변경 | 양측 합의 | 운영관리 협의체 심의 | 변경 요청 후 20영업일 내 결정`

**차트1. α 값에 따른 부담률 변화** (2장 보조)
- 차트 종류 : 꺾은선 2개
- 축 : 가로 = α (0 ~ 1), 세로 = 기관별 부담률(%)
- 계열 : 은행 부담률 / 상호금융 부담률
- 마커 : α = 0.5(권고값) 지점, α = 0(순수 사용량 비례)·α = 1(순수 균등) 양극단 표시
- 목적 : 협의 시 α 조정의 영향을 한 화면에서 확인

**차트2. 월별 부담액 추이 및 사후 정산** (4장 보조 · 별지)
- 차트 종류 : 누적 세로 막대 + 꺾은선
- 축 : 가로 = 개시 후 월(1~12), 세로 = 부담액
- 계열 : F / V / D 누적 막대, 꺾은선 = 사용량 점유율
- 표시 : 12개월 시점에 **사후 정산 마커**와 조정 상한(±10%p) 밴드

## 5. 인접 절과의 경계 / 인용 근거

### 경계 자기점검

- **Ⅲ.4.4(과제3)와의 경계** : 본 절은 **산식과 합의 절차**를 담당하고, **계측 기능의 구현 방식**(게이트웨이 태깅, 수집 파이프라인, 통합관리 화면)은 Ⅲ.4.4가 담당한다. 계측 차원의 정의(기관·부서/조합·서비스·모델·자원 유형·비용 성격)는 두 절이 **동일하게 사용하는 공유 값**이며, 본 절의 산식 초안이 Ⅲ.4.4의 계측 요건에 선행 입력된다(Ⅲ.1.2 접합면 ③).
- **Ⅲ.2.3(이원 산출물 전략)과의 경계** : DL4-1을 **A형(단일 문서)** 으로 판정한 근거는 Ⅲ.2.3이 제시했다. 본 절은 그 판정을 전제로 협약 별지 규격의 문서를 작성한다.
- **Ⅲ.2.5(위험요소)와의 경계** : 합의 결렬·지연 위험(R-03)의 트리거와 대체 경로는 Ⅲ.2.5가 정의했다. 본 절은 그 대체 경로(부분 합의 + 잠정 비율)를 **협의 일정에 반영**했을 뿐 위험 레지스터를 재기술하지 않았다.
- **Ⅲ.4.2(과제1)와의 경계** : 데이터 Owner·Steward 구분과 「Owner = 중앙회 / Steward = 은행」 구조의 식별은 Ⅲ.4.2.6이 담당했다. 본 절은 그 구조를 **협약 제23조로 반영**하는 부분만 다룬다.
- **Ⅲ.4.3(과제2)와의 경계** : 성과지표 중 사용량 관련 지표는 **성과 관점**이며, 본 절의 계측은 **정산 관점**이다. 같은 원천 데이터를 쓰되 목적과 집계 단위가 다르다.
- **Ⅳ.2(관리방안)와의 경계** : 발주처 내부 조직·부서 간 이슈 대응은 Ⅳ.2가 담당한다. 본 절의 운영관리 체계는 **은행–중앙회 간 기관 대 기관 관계**에 한정한다.
- **본 사업 범위와 협약 체결 행위의 구분** : 협약의 **당사자는 은행과 중앙회**이며 제안사는 당사자가 아니다(Ⅲ.1.2 Scope Out). 본 절이 제시하는 것은 **별지 문안·쟁점 정리표·대안 3안·시산표**이며, 서명은 양 기관이 한다.
