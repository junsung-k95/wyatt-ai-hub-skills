## 1. 이 문서가 답해야 할 질문

> **이 사업을 어떤 단계로 쪼개어 수행하며, 각 단계에서 무엇을 입력받아 무엇을 내놓는가?**

이 질문에 답하지 못하면 분량과 무관하게 실패한 문서다.

## 2. 반드시 본문에 들어가야 할 것

1. **단계 정의**(예: 진단 → 설계 → 정합화 → 검증 → 이관). 각 단계마다 [입력 / 핵심활동 / 산출 / 종료조건]을 표로. 종료조건은 판정 가능한 문장이어야 함
2. Phase1/Phase2가 이 단계들과 어떻게 겹치는지 — Phase1은 진단·설계·검증을 압축 병렬로 돌린다는 점을 명시
3. **유사 프로젝트 수행 경험을 방법론에 결합**: 어느 단계에서 어떤 경험이 적용되는지 (실적은 Ⅱ.4가 나열하므로 여기서는 '경험 → 방법론 반영' 연결만)
4. 발주처 참여 지점(워크숍·인터뷰·검토회의)을 단계별로 명시 — 현업주도(SC2-10)와 호응
