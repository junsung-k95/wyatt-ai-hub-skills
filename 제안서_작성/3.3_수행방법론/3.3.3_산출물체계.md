# Ⅲ.3.3 산출물 체계 : 종류 · 내역 · 제출시기

> **메타** | 요구사항: `PD-III-3b, GM-13` | Phase: 전기간 | 예상 분량: 2장

---

## 1. 거버닝 메시지

> **산출물 목록은 명칭 나열이 아니라 「받는 즉시 시행되는 문서의 목차」여야 하므로, 19종 전건에 대해 조문·장(章) 수준의 내역과 D+n 제출시기, 이원화 여부, 검수 주체를 명시하고, 제출–검토–협의–보완–승인의 상태 전이에 각각 소요일을 부여한다.**

- **서브메시지 1** — 「내역」을 *"AI 업무규정 : 총칙·적용범위·거버넌스 기구·위험관리·개발이용·소비자보호·보칙"* 수준으로 적는다. 명칭만 나열된 산출물 표는 발주처가 무엇을 받는지 판단하지 못한다.
- **서브메시지 2** — 제출시기는 절대 날짜가 아니라 **D+n**으로 표기하고, **초안 인수 시점과 확정본 인수 시점을 분리**해 표기한다(GM-05 조기 인수 대응).
- **서브메시지 3** — 산출물은 제출로 끝나지 않는다. **제출 → 검토 → 협의 → (보완) → 승인**의 5개 상태와 각 상태의 소요일·수행 주체를 정의하여, 검수가 언제 끝나는지를 사전에 계산한다(GM-14).

**총 산출물 : RFP 명시 19종 + 추가 제안 6종 = 25종** (추가분 중 5종은 기본 범위 내 흡수)

### 2.3 산출물 상태 전이 및 소요일 (GM-14)

RFP는 **검토 → 관련 부서 협의 → (보완) → 승인**의 품질관리 절차 제시를 요구한다. 5개 상태와 소요일을 다음과 같이 정의한다.

| 상태 | 정의 | 수행 주체 | 소요일(초안 인수) | 소요일(확정 인수) | 산출 |
|---|---|---|---|---|---|
| **① 제출** | 제안사가 산출물을 제출하고 접수 확인을 받는다 | 제안사 → 발주처 사업담당 | 1일 | 1일 | 제출 확인서 |
| **② 검토** | 사업담당 부서가 요구사항 커버리지·구조 적정성을 검토한다. **요구사항 ID 단위로 충족/부분충족/미충족 판정**(Ⅲ.1.4 연결) | 발주처 사업담당(AX혁신실) | 3영업일 | 3영업일 | 검토의견서 |
| **③ 관련 부서 협의** | 준법감시·리스크·정보보호·소비자보호 및 **중앙회**가 소관 사항을 검토한다. B형 문서는 병렬 2레인으로 진행(Ⅲ.2.3) | 관련 부서 + 중앙회 | 3영업일 | 5영업일 | 부서 의견 취합표 |
| **④ 보완** | 검토·협의 의견을 반영한다. 의견 중 **미반영 항목은 사유를 명시**한다 | 제안사 | 3영업일 | 5영업일 | 의견 반영 대조표 |
| **⑤ 승인** | 승인권자가 인수를 확정한다. 확정본은 버전 `v1.0` 부여 | 발주처 승인권자 | 1영업일 | 2영업일 | 인수확인서 |
| | **합계** | | **10영업일** | **15영업일** | |

**상태 전이 규칙 3가지**
1. **보완이 2회를 초과하면 상태를 「보류」로 전환**하고, 쟁점을 목록화하여 사업담당 부서와 조정 회의를 갖는다. 무한 보완 반복을 차단하기 위한 규칙이다.
2. **부분충족 판정 항목만 보완 대상**이 된다. 산출물 전체를 다시 쓰지 않는다(Ⅲ.1.4의 ID 단위 판정과 연결).
3. **승인 이후의 개정은 새로운 상태 전이를 시작**하며, 규제 변경에 따른 개정은 Ⅲ.2.4의 부분 재검수 규칙(2·5·15영업일)을 적용한다.

### 2.4 제출 시기의 밀집 구간과 대응

D+n 기준으로 산출물 제출이 몰리는 구간이 두 곳 있다.

| 밀집 구간 | 대상 | 동시 진행 검수 | 대응 |
|---|---|---|---|
| **D+30 ~ D+45** | DL1-2, DL1-3, DL1-4, DL2-1, DL2-2, DL1-5, DL4-1(초안) — **7건** | 은행 5건 + 중앙회 3건 | ① 초안 인수를 D+17~D+24로 분산해 확정 인수 부하를 줄인다 ② 검토 대상을 **요구사항 ID로 한정**해 검토 소요를 3영업일로 유지한다 ③ 관련 부서 협의를 **부서별 소관 조문만** 회람하여 병렬화한다 |
| **D+125 ~ D+140** | DL1-7, DL2-4, DL2-5, DL2-6, DL3-2, DL1-8 — **6건** | 은행 6건 + 중앙회 5건 | ① Phase2 산출물의 초안 인수를 D+90~D+115에 앞당겨 배치한다 ② DL1-9(최종보고서)를 D+148로 두어 나머지 확정 이후 작성한다 |

**검수 부하의 계량** — 밀집 구간에서 발주처가 동시에 검토하는 문서는 최대 **7건 / 15영업일**이다. 부서별로 나누면 준법감시 3건, 정보보호 2건, 리스크 2건 수준이며, 이 배분을 착수 시 발주처와 확인하여 검수 담당자를 사전 지정한다.

## 3. 제안서용 요약 · 논리 구조

**논리 골격 : [내역 규율] → [전수 체계] → [추가 제안] → [상태 전이] → [밀집 대응]**

- **[내역 규율]** 명칭 나열 ✗ / **조문·장(章) 수준 목차** ○
  - 예 : *AI 업무규정 = 총칙 / 거버넌스 기구 / 적용대상 판단 / 고영향 분류 / 위험평가·등급 / 등급별 통제 / 개발·이용·운영 / 보안 / 소비자보호 / 문서화·보존 / 교육 / 위반 처리 / 보칙·부칙*
- **[전수 체계]** 19종 × [내역 / Phase / **초안 인수 D+n** / **확정 인수 D+n** / 이원화 A·B·C / 검수 주체]
  - Phase1 9종 : DL1-1~1-5, DL2-1, DL2-2, DL4-1, DL4-2 → 확정 인수 **D+30 ~ D+58**
  - Phase2 10종 : DL1-6~1-9, DL2-3~2-6, DL3-1, DL3-2 → 확정 인수 **D+110 ~ D+148**
  - 이원화 : **A 단일 5종 / B 공통+델타 8종 / C 완전분리 6종**
- **[추가 제안]** RFP 19종 + **추가 6종 = 25종**, 5종은 기본 범위 흡수 / 1종(ADD-5 학습데이터 적법성 검토서)만 별도 공수 검토
- **[상태 전이]** **제출 → 검토 → 관련 부서 협의 → (보완) → 승인** 5상태 (GM-14)
  - 소요 : **초안 10영업일 / 확정본 15영업일**
  - 규칙 3개 : **보완 2회 초과 시 「보류」 전환 + 조정회의** / **부분충족 항목만 보완**(전체 재작성 금지) / 승인 후 개정은 부분 재검수 규칙 적용
- **[밀집 대응]** 두 구간 — **D+30~45 (7건)**, **D+125~140 (6건)**
  - 대응 : 초안 인수 앞당겨 분산 / 검토 대상을 요구사항 ID로 한정 / 부서별 소관 조문만 병렬 회람
  - 최대 검수 부하 = **7건 / 15영업일**, 부서별 2~3건 → 착수 시 검수 담당자 사전 지정

## 4. 시각적 표현 방안

### (a) 슬라이드 분할 구조 — 2장

- **1장 : `전면 표`** — 산출물 19종 전수 체계표(내역 요약형). 상단에 계열별 건수 요약 블록
- **2장 : `상하 2분할`** — 위 = 산출물 캘린더(간트), 아래 = 상태 전이 흐름도 + 밀집 구간 대응

### (b) 도해 지시

**1장 — 산출물 전수 체계표**
- 19행을 **계열별 4블록**(과제1 9종 / 과제2 6종 / 과제3 2종 / 과제4 2종)으로 나누고 블록 사이에 굵은 구분선
- 「주요 내역」 열이 표의 절반 폭을 차지하도록 배분 — **내역의 구체성이 이 절의 존재 이유**이므로 지면을 여기에 준다
- 「이원화」 열은 A/B/C를 **색 배지**로 표기(A = 단색 원 / B = 반분할 원 / C = 두 개 원). 배지 모양만으로 유형이 읽히게 한다
- 「초안 인수」 열에 값이 있는 행(6건)에는 **별표 마커**를 붙여 조기 인수 대상임을 표시
- 표 하단에 추가 제안 산출물 6종을 **다른 배경색 행**으로 이어 붙이고 `ADD` 배지 부착

**2장 상단 — 산출물 캘린더 (간트)**
- 세로 = 산출물 25종(19 + 추가 6), 가로 = D+0 ~ D+150
- 막대 = 작성 구간, **속이 빈 마름모 = 초안 인수**, **채운 마름모 = 확정 인수**
- **Phase1 구간(D+0~D+60)을 음영 처리**하고, 그 안에 9건의 마름모가 몰려 있는 모습을 그대로 보이게 한다
- 두 밀집 구간(D+30~45, D+125~140)에 **세로 적색 밴드**를 덧씌우고 건수 라벨(7건 / 6건)
- 각 산출물 행 좌측에 이원화 배지, 우측에 검수 주체 아이콘(은행 / 중앙회 / 공동)
- 상단에 보조 라인 차트 : **주차별 동시 검수 건수** — 밴드 구간에서 솟는 모양이 드러나야 한다

**2장 하단 좌 — 상태 전이 흐름도**
- 좌→우 5단계 : `① 제출` → `② 검토` → `③ 관련 부서 협의` → `④ 보완` → `⑤ 승인`
- 각 단계 아래 소요일 배지 **2개 병기**(초안 / 확정본)
- ④에서 ②로 되돌아가는 **역방향 화살표**를 그리고 그 위에 **"2회 초과 시 → 보류"** 를 적색으로 표기. 이 되돌림 루프의 차단 규칙이 이 도해의 핵심
- ③ 단계 아래에 **병렬 2레인 아이콘**(은행 / 중앙회) 삽입 → Ⅲ.2.3과 연결
- ⑤ 다음에 `v1.0` 버전 배지, 그 우측에 점선으로 **「규제 변경 시 → 부분 재검수(2·5·15영업일)」** 분기 표시 → Ⅲ.2.4와 연결

**2장 하단 우 — 밀집 구간 대응 카드 2장**
- 카드 : `구간` / `대상 건수` / `동시 검수 부하` / `대응 3개`
- 각 카드에 소형 막대 차트(부서별 검수 건수 : 준법 3 / 정보보호 2 / 리스크 2)

## 5. 인접 절과의 경계 / 인용 근거

### 경계 자기점검

- **Ⅲ.4.6(산출물 목록·세부내용 및 소유권)과의 경계 — 이 절에서 가장 중요한 경계** : 본 절은 **「제출 시기 중심」**, Ⅲ.4.6은 **「내용과 권리 중심」** 으로 분담한다. 본 절은 각 산출물의 목차 수준 내역과 D+n·상태 전이를 다루고, **분량 수준·제출 형식(문서/서식/시트)·저작권 귀속·양도 조건·독자 정보 표시**는 Ⅲ.4.6이 다룬다. 두 절의 표는 컬럼 구성이 다르며 중복되지 않는다.
- **Ⅳ.3(품질보증)으로 넘긴 것** : 검수 조직 구성, 검수 판정 기준의 세부, 검증 방법, 산출물 형상관리 도구. 본 절은 **상태와 소요일·전이 규칙**만 정의했다.
- **Ⅲ.2.2로 넘긴 것** : 마일스톤 캘린더의 역산 논리, 버퍼 배치, 외부 일정 변경 시 재조정. 본 절의 D+n은 그 캘린더에 **연동된 값**이며 재산정 주체는 Ⅲ.2.2다.
- **Ⅲ.2.3으로 넘긴 것** : 이원화 유형의 판정 근거와 병렬 검수 4단계의 상세. 본 절은 판정 **결과값(A/B/C)** 만 표기했다.
- **Ⅲ.4.7로 넘긴 것** : 추가 제안 산출물 6종의 **규제 근거 조항·미대응 리스크·공수 판정의 상세**. 본 절은 목록과 요약 근거만 제시했다.
- **Ⅲ.4.2~4.5로 넘긴 것** : 각 산출물의 내용을 **어떻게 만드는가**. 본 절은 목차만 제시했다.

- **[가정]** Phase2 산출물의 D+n(D+90~D+148)은 Phase1이 D+60에 종료된다는 전제로 산정하였다. Phase1이 연장되면 동일 폭으로 순연한다.
