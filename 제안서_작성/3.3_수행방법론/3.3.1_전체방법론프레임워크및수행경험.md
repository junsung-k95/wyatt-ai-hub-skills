# Ⅲ.3.1 전체 방법론 프레임워크 및 수행 경험

> **메타** | 요구사항: `PD-III-3a` | Phase: 전기간 | 예상 분량: 2장

---

## 1. 거버닝 메시지

> **본 사업은 「진단 → 설계 → 정합화 → 검증 → 이관」 5단계로 수행하되, Phase1은 이 5단계를 순차로 돌릴 시간이 없으므로 진단·설계·검증을 10월 3개 과제에 한정해 압축 병렬로 돌리고 Phase2에서 전사로 확장하는 이중 트랙 구조를 적용한다.**

- **서브메시지 1** — 각 단계는 **[입력 / 핵심활동 / 산출 / 종료조건]** 으로 정의하며, 종료조건은 "완료한다"가 아니라 **판정 가능한 문장**으로 쓴다. 종료조건이 판정되지 않으면 단계가 끝나지 않고 겹쳐 흐른다.
- **서브메시지 2** — 「정합화」 단계는 일반적 컨설팅 방법론에 없는 단계다. 본 사업은 과제 4개의 산출물이 **서로의 입력 규격**이 되므로(Ⅲ.1.2 접합면 5개), 설계 후 검증 전에 **접합면을 맞추는 단계를 명시적으로 세운다.**
- **서브메시지 3** — 유사 프로젝트 경험은 실적 나열이 아니라 **방법론의 특정 단계에 반영된 형태**로 제시한다. 경험이 어느 단계의 어떤 활동을 바꾸었는지가 이 절의 응답이다.

---

## 2. 본문

### 2.1 5단계 방법론 프레임워크

| 단계 | 명칭 | 한 줄 정의 |
|---|---|---|
| **S1** | **진단(Diagnose)** | 현행 내규·조직·서비스·데이터·플랫폼을 규제 기준선과 대조해 공백을 판정한다 |
| **S2** | **설계(Design)** | 공백을 메우는 규범·절차·기준·산식을 **조문·서식 수준**으로 만든다 |
| **S3** | **정합화(Align)** | 과제 간 접합면과 기관 간 델타를 맞춰 산출물이 서로 모순되지 않게 한다 |
| **S4** | **검증(Validate)** | 만든 것을 실제 서비스에 적용해 보고, 발견된 결함을 반영한다 |
| **S5** | **이관(Transfer)** | 발주처가 스스로 운영하도록 교육·인수인계하고 잔여 과제를 넘긴다 |

### 2.2 단계별 상세 정의

#### S1. 진단 (Diagnose)

| 항목 | 내용 |
|---|---|
| **입력** | 현행 내규 전문, 조직도·위원회 운영규정, AI서비스 인벤토리(10월 3개 과제 사양 포함), 데이터 관리 현황 자료, 현행 플랫폼 구성 정보, 규제 기준선(AI기본법·시행령, 금융분야 인공지능 가이드라인 점검항목 99개, AI RMF, 보안 안내서) |
| **핵심활동** | ① 자료요청·인터뷰·현장 확인 ② 규범 대조 매트릭스 작성(규범 조항 ↔ 대응 내규 조문) ③ 충족/부분충족/공백 3등급 판정 ④ 공백을 개선과제로 전환하고 과제1~4에 배정 ⑤ 10월 3개 과제 선별 진단 우선 수행 |
| **산출** | 규범 대조 매트릭스, 갭 판정 결과표(5개 영역 × 3등급), 개선과제 목록 및 과제 배정표, 자료 미확보 항목 목록 |
| **종료조건** | ① 점검항목 99개 및 AI기본법 관련 조항 **전건에 대해 판정값이 부여**되어 미판정 0건 ② 공백 판정 항목이 **전건 개선과제로 전환**되어 미전환 0건 ③ 자료 미확보로 판정 불가한 항목은 **그 사실과 영향이 문서에 기재**됨(추정으로 채우지 않음) |
| **발주처 참여** | 착수 워크숍 1회(반일), 부서별 인터뷰(5개 영역 × 2~3인), 진단 결과 검토회의 1회 |

#### S2. 설계 (Design)

| 항목 | 내용 |
|---|---|
| **입력** | 개선과제 목록, 규제 기준선, 발주처 내규 서식 표준, 현행 플랫폼 제약조건 |
| **핵심활동** | ① 규정·준칙 조문 작성 및 현행–개정 대비표 작성 ② 위험평가 항목·배점·등급 산정식 설계 ③ 라이프사이클 단계·게이트·체크리스트 설계 ④ 비용 배분 산식 설계 및 시산 ⑤ 목표 아키텍처·로드맵 설계 ⑥ 매뉴얼 작성(서식·화면·직위·소요일 내장) |
| **산출** | 산출물 19종의 초안(v0.x), 기관별 델타 후보 목록, 시산 결과표 |
| **종료조건** | ① 각 산출물이 **초안 인수 기준**(구조·목차·핵심 판단 확정)을 충족 ② 선택지가 있는 사안은 **대안 비교 + 권고안 + 근거**가 문서에 포함됨 ③ 산식류는 **숫자 예시 계산이 1회 이상 포함**됨 |
| **발주처 참여** | 설계 워크숍(과제별 1~2회), 조문 검토회의, 임원 개별 협의(책무구조도) |

#### S3. 정합화 (Align)

| 항목 | 내용 |
|---|---|
| **입력** | 산출물 초안 전체, 접합면 5개 정의(Ⅲ.1.2), 기관별 델타 후보 12개 항목(Ⅲ.2.3) |
| **핵심활동** | ① **접합면 대조** — 과제1 위험등급 ↔ 과제3 게이트 조건 / 과제2 단계 명칭 ↔ 과제3 상태값 / 과제3 계측 단위 ↔ 과제4 정산 변수 / 과제4 기준 ↔ 부속협약 별지 / 과제1 평가 ↔ 과제2 게이트 호출 ② **용어 통일** — 라이프사이클 단계 명칭, 위험등급 명칭, 조직 명칭을 전 산출물에서 일치시킨다 ③ **기관 델타 확정** — 델타 후보를 조문 단위로 확정하고 「기관별 상이 항목 일람표」 작성 ④ **조문 참조 관계도** 작성 |
| **산출** | 접합면 정합 확인서, 용어 사전(약어표 포함), 기관별 상이 항목 일람표, 조문 참조 관계도 |
| **종료조건** | ① 접합면 5개 **전건에 대해 전달 규격이 문서로 확정**되고 양측 산출물에 동일하게 기재됨 ② 동일 개념에 서로 다른 용어가 사용된 사례 **0건** ③ 델타 후보 12개 항목이 **전건 확정 또는 보류 목록으로 분류**됨 |
| **발주처 참여** | 합동 조정회의(산출물별 1회), 용어 확정 검토 |

> **이 단계를 별도로 세운 이유** — 정합화를 검증 단계에 흡수하면, 검증에서 발견된 결함이 접합면 불일치인지 설계 오류인지 구분되지 않는다. 접합면을 먼저 맞춘 뒤 검증에 들어가야 검증 결과가 해석된다.

#### S4. 검증 (Validate)

| 항목 | 내용 |
|---|---|
| **입력** | 정합화 완료 산출물, 10월 3개 과제 및 개발 중 AI서비스, 게이트 체크리스트 |
| **핵심활동** | ① **거버넌스 적용 시뮬레이션** — 실제 서비스를 라이프사이클에 태워 게이트별 판정을 수행 ② **매뉴얼 워크스루** — 업무 미경험자가 매뉴얼만으로 1개 단계 수행 ③ **자체 사전점검** — 보안성 원칙 점검항목 38개 대조(기획·개발·운영자가 아닌 별도 인력 수행) ④ **산식 시산 검증** — 가상 사용량 투입 후 분담액 산출 ⑤ 발견 결함의 개선 반영 및 재확인 |
| **산출** | 시뮬레이션 결과 보고서, 발견 결함 및 개선 반영 이력, 자체 사전점검 결과서, 시산 검증표 |
| **종료조건** | ① 시뮬레이션에서 발견된 결함이 **전건 개선 반영 또는 잔여 이슈로 등재**됨 ② 매뉴얼 워크스루가 **중단 없이 완료**됨(중단 지점은 매뉴얼 보완 후 재수행) ③ 산식 시산 결과가 양 기관에 **회람·확인**됨 |
| **발주처 참여** | 시뮬레이션 참여(현업·IT·리스크·준법·정보보호), 워크스루 수행자 배정 |

#### S5. 이관 (Transfer)

| 항목 | 내용 |
|---|---|
| **입력** | 확정 산출물 전체, 잔여 이슈 목록, 미반영 규제 변경 목록 |
| **핵심활동** | ① **실제 케이스 기반 교육** — 시뮬레이션에서 다룬 실제 서비스를 교재로 사용 ② 역할별 교육(실무자·관리자·감사인) ③ 인수인계 문서화 및 잔여 과제 이관 ④ 사후지원 체계 합의 |
| **산출** | 교육 교재 및 실시 결과, 인수인계서, 잔여 이슈 이관 목록, AI 거버넌스 수립 최종 보고서 |
| **종료조건** | ① 역할별 교육이 **계획 대상 전원에 대해 실시 완료** ② 잔여 이슈가 **전건 이관 주체·시점과 함께 문서화** ③ 최종 보고서가 승인됨 |
| **발주처 참여** | 교육 참석, 인수 확인 |

### 2.3 Phase 구조와 단계의 중첩 — 이중 트랙

Phase1(2개월)에서 S1~S5를 순차로 돌리면 각 단계에 12일밖에 배정되지 않아 성립하지 않는다. **적용 범위를 좁혀 압축 병렬로 돌리는 것**이 해법이다.

| 구분 | **Phase1 (D+0~D+60)** | **Phase2 (D+61~D+150)** |
|---|---|---|
| 적용 범위 | **10월 3개 과제에 한정** | 전사 AI서비스로 확장 |
| S1 진단 | 선별 진단 (3개 과제 + 관련 내규·보안 영역) — D+3~D+20 | 전수 진단 (데이터·플랫폼 전 영역) — D+61~D+80 |
| S2 설계 | 필수 규범·평가체계·보안대책·비용산식 — D+10~D+45 (**진단과 20일 중첩**) | 라이프사이클·매뉴얼·데이터거버넌스·아키텍처 — D+70~D+120 |
| S3 정합화 | 접합면 중 **③계측 요건**과 **④협약 별지** 우선 — D+30~D+50 | 접합면 5개 전건 + 용어·델타 확정 — D+110~D+130 |
| S4 검증 | 자체 사전점검 + 산식 시산 — D+24~D+55 | 거버넌스 적용 시뮬레이션 + 워크스루 — D+120~D+140 |
| S5 이관 | (Phase1 완료보고) | 교육·인수인계·최종보고 — D+135~D+150 |

**중첩의 원칙 3가지**
1. **선행 단계의 종료조건이 확정되기 전에 후행 단계를 시작하되, 확정 대상 항목에 의존하는 작업은 시작하지 않는다.** 예: 진단이 끝나기 전에 보안대책서 작성을 시작하되, 갭 판정 결과를 인용하는 장(章)은 판정 확정 후 작성한다.
2. **Phase1의 압축은 "빠르게"가 아니라 "좁게"로 달성한다.** 품질 기준을 낮추지 않고 적용 범위를 3개 과제로 좁힌다.
3. **Phase1에서 만든 것은 Phase2에서 확장하되 다시 만들지 않는다.** Phase1의 위험평가 실시 기록·승인 절차 실행 경로가 Phase2 산출물의 원형이 된다(Ⅲ.1.3 참조).

### 2.4 수행 경험의 방법론 반영

유사 프로젝트 경험은 실적 나열(Ⅱ.4)이 아니라 **방법론의 특정 단계를 바꾼 형태**로 제시한다. 다음 5건이 본 방법론에 반영된 경험이다.

| # | 경험 영역 | 무엇을 겪었는가 | 방법론의 어느 지점을 바꾸었는가 |
|---|---|---|---|
| 1 | 제1금융권 AI 거버넌스 수립 | 규정 개정안이 **보고서 문체로 작성되어 내규 심사 부서에서 반려**됨 | **S2의 산출 규격**을 「제언」이 아닌 「조문 + 현행–개정 대비표」로 고정. S2 종료조건에 초안 인수 기준을 명시 |
| 2 | 금융권 위험평가체계 구축 | 위험등급 기준을 만든 뒤 **실제 서비스에 적용해 보니 대부분이 한 등급에 몰림** | **S4에 산식·등급 시뮬레이션을 필수 활동으로 편입.** 설계 종료가 아니라 검증 통과를 확정 시점으로 정의 |
| 3 | 다기관 공동 플랫폼 비용 정산 | 배분 비율 합의 후 **정산 변수 중 일부가 계측되지 않아 산식이 실행되지 않음** | **S3 정합화에 「계측 가능성 검증」을 접합면 항목으로 편입.** 산식 설계 시 계측 가능성을 제약조건으로 선언 |
| 4 | 감독당국 실사 대응 | 실사 현장에서 **증적이 여러 부서에 흩어져 있어 즉시 제출하지 못함** | **S2 설계 시점에 증적 항목별 적재 위치·형식을 지정**하고, S4에서 「서비스 단위 조회」로 확인하는 절차 추가 |
| 5 | 금융회사 업무 매뉴얼 수립 | 매뉴얼이 **작성자에게만 이해되는 수준**이어서 담당자 교체 후 작동하지 않음 | **S4에 「미경험자 워크스루」를 종료조건으로 편입.** 워크스루 중단 지점을 매뉴얼 보완 대상으로 처리 |

각 경험의 구체적 상황과 그때 적용한 해법은 Ⅲ.3.4에서 사례 카탈로그로 제시한다. 본 절은 **경험 → 방법론 반영**의 연결만 기술한다.

### 2.5 발주처 참여 지점 (SC2-10 호응)

RFP는 *"현업이 적극적으로 참여하는 AI서비스 개발 협력 프로세스"*(SC2-10)를 요구한다. 본 방법론은 발주처를 검토자가 아니라 **수행 주체의 일부**로 배치한다.

| 단계 | 참여 형태 | 대상 | 횟수 |
|---|---|---|---|
| S1 | 착수 워크숍 | 전 관련 부서 | 1회(반일) |
| S1 | 부서별 인터뷰 | 내규·조직·AI서비스·데이터·플랫폼 5개 영역 담당 | 영역당 2~3인 |
| S1 | 진단 결과 검토회의 | AX혁신실 + 관련 부서 | 1회 |
| S2 | 설계 워크숍 | 과제별 관련 부서 | 과제당 1~2회 |
| S2 | 조문 검토회의 | 준법감시·리스크·정보보호 | 산출물별 1회 |
| S2 | 임원 개별 협의 | 책무 배분 대상 임원 | 동일 주간 병렬 |
| S3 | 합동 조정회의 | 은행 + 중앙회 | 산출물별 1회 |
| S4 | **시뮬레이션 참여** | 현업·IT·리스크·준법·정보보호 | 3개 과제 × 1회 |
| S4 | 매뉴얼 워크스루 수행 | 해당 업무 미경험 실무자 | 매뉴얼별 1인 이상 |
| S5 | 역할별 교육 | 실무자·관리자·감사인 | 역할별 1회 이상 |

**S4의 시뮬레이션 참여가 가장 중요한 지점이다.** 여기서 발주처 직원이 실제로 게이트를 통과시켜 보아야, 이관 이후 스스로 운영한다. 교육을 이관 단계에서 처음 하는 방식은 채택하지 않는다.

## 3. 제안서용 요약 · 논리 구조

**논리 골격 : [단계 정의] → [단계별 계약] → [Phase 중첩] → [경험 반영] → [참여 설계]**

- **[단계 정의]** **S1 진단 → S2 설계 → S3 정합화 → S4 검증 → S5 이관**
  - **S3 정합화는 일반 방법론에 없는 단계** ← 과제 산출물이 서로의 입력 규격이므로(접합면 5개), 검증 전에 접합면을 맞춰야 검증 결과가 해석된다
- **[단계별 계약]** 각 단계 = **[입력 / 핵심활동 / 산출 / 종료조건]**, 종료조건은 **판정 가능한 문장**
  - S1 : *점검항목 99개 미판정 0건 · 공백 미전환 0건 · 미확보 항목은 사실 기재(추정 금지)*
  - S2 : *초안 인수 기준 충족 · 선택지는 대안+권고+근거 · 산식은 숫자 예시 1회 이상*
  - S3 : *접합면 5개 전건 전달 규격 확정 · 용어 불일치 0건 · 델타 12항목 확정 또는 보류 분류*
  - S4 : *결함 전건 반영 또는 등재 · 워크스루 중단 없이 완료 · 시산 결과 양 기관 회람*
  - S5 : *교육 전원 실시 · 잔여 이슈 이관 주체·시점 문서화 · 최종보고서 승인*
- **[Phase 중첩]** 순차 불가(단계당 12일) → **이중 트랙**
  - Phase1 = **범위를 3개 과제로 좁혀** S1~S4 압축 병렬 / Phase2 = 전사 확장
  - 원칙 : *"빠르게"가 아니라 "좁게"* / 선행 종료조건 미확정 항목만 대기 / **Phase1 결과물이 Phase2 원형**
- **[경험 반영]** 실적 나열 ✗ / **경험이 바꾼 방법론 지점** ○ (5건)
  - 조문 반려 경험 → **S2 산출 규격 = 조문 + 대비표**
  - 등급 쏠림 경험 → **S4에 등급 시뮬레이션 필수화**
  - 계측 불가 경험 → **S3에 계측 가능성 검증 편입**
  - 증적 산재 경험 → **S2에서 적재 위치·형식 지정**
  - 매뉴얼 미작동 경험 → **S4 미경험자 워크스루 종료조건화**
- **[참여 설계]** 발주처 = 검토자 ✗ / **수행 주체** ○ — 10개 참여 지점, 핵심은 **S4 시뮬레이션 직접 수행**

## 4. 시각적 표현 방안

### (a) 슬라이드 분할 구조 — 2장

- **1장 : `4분할 세로 흐름`** (실제로는 5분할) — S1~S5를 좌→우 흐름 카드로 배치, 하단에 Phase 오버레이 띠
- **2장 : `상하 2분할`** — 위 = 이중 트랙 중첩도(Phase1/Phase2 병렬 간트), 아래 = 경험 반영표 + 발주처 참여 지점 표

### (b) 도해 지시

**1장 상단 — 5단계 흐름 카드**
- 카드 5장을 좌→우로 배치하되 **S3 카드만 세로로 길게** 그려 다른 카드보다 크게 만든다. 본 사업 고유의 단계임을 크기로 표현
- 각 카드는 4개 슬롯 : `입력`(상단 좌측 화살표 유입) / `핵심활동`(중앙, 번호 목록) / `산출`(하단 아이콘) / `종료조건`(카드 하단 별도 밴드, 다른 배경색)
- **종료조건 밴드를 카드마다 같은 색으로 통일**하고 굵은 테두리 — 5개 카드를 관통하는 가로 띠처럼 보이게 하여 *"단계는 종료조건으로 끝난다"* 를 강조
- 카드 사이 화살표 위에 전달물 라벨(`갭 판정 결과` → `산출물 초안` → `정합 확인서` → `검증 결과` → `인수인계서`)
- S3 카드 안에는 접합면 5개를 소형 아이콘으로 표시하고 각각에 번호 배지 ①~⑤

**1장 하단 — Phase 오버레이 띠**
- 5단계 카드 아래를 가로지르는 2개 띠 : 위 = **Phase1(적용 범위 = 3개 과제)**, 아래 = **Phase2(전사 확장)**
- Phase1 띠는 S1~S4 구간에서 **여러 단계에 걸쳐 겹쳐 있는 모습**으로 그린다(압축 병렬). Phase2 띠는 상대적으로 순차적으로
- 두 띠 사이 경계에 `D+60` 표시
- Phase1 띠 위에 *"좁게, 압축 병렬"*, Phase2 띠 위에 *"넓게, 확장"* 라벨

**2장 상단 — 이중 트랙 중첩 간트**
- 세로 = S1~S5, 가로 = D+0 ~ D+150
- 각 단계에 **막대 2개**(Phase1 트랙 = 강조색 / Phase2 트랙 = 보조색)
- Phase1 트랙 막대들이 **서로 겹치는 구간을 빗금으로 표시**하고 중첩 일수 라벨(예: 진단·설계 20일 중첩)
- 세로 점선으로 D+60 Phase 경계 표시
- 우측에 중첩 원칙 3개를 짧은 문장으로 세로 배치

**2장 하단 좌 — 경험 반영표**(아래 표2)

**2장 하단 우 — 발주처 참여 지점**
- 5단계 축 위에 참여 지점 10개를 **아이콘 마커**로 배치
- 마커 크기는 참여 규모에 비례
- **S4의 「시뮬레이션 참여」 마커만 강조색 + 확대**하고 *"여기서 직접 게이트를 통과시켜 봐야 이관 후 스스로 운영한다"* 주석

## 5. 인접 절과의 경계 / 인용 근거

### 경계 자기점검

- **Ⅲ.3.2로 넘긴 것** : 각 단계에서 사용하는 **개별 기법·분석도구의 비교와 장단점**(갭분석, 규제 매핑, 위험평가 워크숍, 시나리오 시뮬레이션, 체크리스트 감사, 벤치마킹, 원가 기반 배분 모형). 본 절은 단계의 **핵심활동**만 나열했고 기법을 비교하지 않았다.
- **Ⅲ.3.3으로 넘긴 것** : 산출물 19종의 목차 수준 내역과 제출 시기. 본 절은 단계별 산출을 **묶음 단위**로만 표기했다.
- **Ⅲ.3.4로 넘긴 것** : 유사 프로젝트 사례의 **구체적 상황과 적용 해법**. 본 절은 **경험 → 방법론 반영의 연결**만 기술했고 사례를 서술하지 않았다.
- **Ⅱ.4(관련 사업실적)로 넘긴 것** : 실적의 나열, 발주처·계약금액·기간. 본 절은 실적을 나열하지 않았다.
- **Ⅲ.1.3·Ⅲ.2.2로 넘긴 것** : 과업 우선순위와 D+n 일정. 본 절의 Phase 중첩표는 **단계와 Phase의 관계**를 보이기 위한 것이며, 마일스톤 일정은 Ⅲ.2.2가 확정한다.
- **Ⅲ.4.1로 넘긴 것** : 진단의 **대상 영역·도구·판정 기준의 상세**. 본 절은 S1의 입력·활동·종료조건만 정의했다.
- **Ⅴ.1(교육 및 변화관리)로 넘긴 것** : 교육 커리큘럼·기간·장소·대상의 상세. 본 절은 S5의 활동으로만 언급했다.

- **[가정]** 발주처 참여 지점의 횟수(워크숍 1회, 인터뷰 영역당 2~3인, 설계 워크숍 과제당 1~2회 등)는 제안사 계상치다. 착수 시 발주처의 가용 일정과 인력 상황을 반영해 확정한다.
- **[가정]** S4의 매뉴얼 워크스루 수행자로 「해당 업무 미경험 실무자 1인 이상」을 전제했다. 배정 가능한 인력이 없을 경우 제안사 내 해당 업무 미참여 컨설턴트가 대행하되, 그 사실을 검증 결과 보고서에 명시한다.
- **[가정]** 수행 경험 5건은 제안사의 유사 사업 수행 이력에 근거한 것이며, 발주처 비공개 의무를 고려하여 본 절에서는 사업 유형 수준으로만 표기했다. 업종·규모 수준의 식별 정보는 Ⅲ.3.4에서 제시하고, 계약 상대방을 특정하는 정보는 제시하지 않는다.
- **[가정]** Phase2 단계 구간(D+61~D+150)은 Phase1 종료 시점이 D+60이라는 전제로 산정했다. Phase1이 연장되면 Phase2 단계 구간을 동일 폭으로 순연하고, 순연 사유와 영향을 발주처에 보고한다.
