# Ⅲ.3.2 단계별 기법 · 분석도구 및 방법론의 특징 · 장단점

> **메타** | 요구사항: `PD-III-3a, PD-III-3d` | Phase: 전기간 | 예상 분량: 2장

---

## 1. 거버닝 메시지

> **기법은 만능이 아니므로 7개 기법 각각의 유효 조건과 약점을 먼저 드러내고, 약점이 서로를 보완하도록 조합해 배치한다 — 특히 「규제 매핑」의 형식적 충족 판정 약점은 「시나리오 시뮬레이션」이, 「위험평가 워크숍」의 주관성 약점은 「체크리스트 감사」가 상쇄하도록 단계에 배치한다.**

- **서브메시지 1** — RFP Ⅳ-1 작성순서 표는 수행방법론 항목에 **「특징 및 장단점」**(PD-III-3d)을 명시적으로 요구한다. 장점만 쓰고 단점 칸을 비우면 요구 미충족이다. 본 절은 7개 기법 전건에 단점을 기재한다.
- **서브메시지 2** — 분석도구는 소프트웨어 이름이 아니라 **본 사업에서 실제로 산출되는 시트·매트릭스·모델**로 제시한다. 도구가 곧 산출물의 일부가 되도록 설계했다.
- **서브메시지 3** — 기법 조합의 근거는 "많이 쓴다"가 아니라 **약점 상쇄 관계**다. 어떤 기법의 약점을 어떤 기법이 메우는지를 명시한다.

## 2. 본문

### 2.1 기법 선택지 메뉴 — 7개 기법 비교

| # | 기법 | 적용 단계 | 언제 쓰는가 | 장점 | 단점 | 본 사업 적용 대상 |
|---|---|---|---|---|---|---|
| **T1** | **규정 갭분석**<br>(Gap Analysis) | S1 진단 | 기준선이 명확하고 현행 문서가 확보될 때 | ① 판정 결과가 조문 단위로 남아 **개선과제 도출이 자동적** ② 커버리지 증명이 쉬움 ③ 재현 가능(다른 사람이 해도 같은 결과) | ① **문서에 있으나 실제로 작동하지 않는 통제**를 충족으로 오판 ② 현행 문서가 미비하면 판정 불가 ③ 조문 간 상호작용을 놓침 | 현행 내규 ↔ AI기본법·가이드라인·AI RMF 대조 |
| **T2** | **규제 매핑**<br>(Regulatory Mapping) | S1 진단 · S3 정합화 | 적용 법령이 다수이고 **의무의 출처를 추적**해야 할 때 | ① 규범 → 조항 → 의무 → 대응 내규의 **추적 경로 확보** ② 법령 개정 시 영향 범위 즉시 산출 ③ 감독기관 소명 자료로 직접 사용 | ① 매핑의 존재가 **이행을 보장하지 않음**(형식적 충족 판정) ② 법령 해석이 갈리는 항목에서 매핑이 자의적 ③ 유지 비용이 큼(개정마다 갱신) | 추적 대상 16개 규범 × 대응 내규 매핑, 규범 대조 매트릭스 |
| **T3** | **위험평가 워크숍**<br>(Risk Workshop) | S2 설계 | 위험 항목·배점을 **조직의 판단으로 정해야** 할 때 | ① 현업의 암묵지가 항목에 반영됨 ② 참여로 인한 **수용성 확보**(나중에 "우리가 정한 기준"이 됨) ③ 부서 간 위험 인식 차이가 드러남 | ① **참여자 구성에 따라 결과가 달라짐**(주관성) ② 목소리 큰 부서의 위험이 과대평가 ③ 워크숍 결과를 그대로 쓰면 배점이 특정 부문에 쏠림 | 위험평가 항목·배점 설계, 등급 임계값 조정 |
| **T4** | **시나리오 기반 시뮬레이션** | S4 검증 | 설계한 절차가 **실제로 통과되는지** 확인해야 할 때 | ① 문서상 충족과 실제 작동의 **차이를 드러냄** ② 참여자가 절차를 몸으로 익힘(이관 효과) ③ 결함 발견 지점이 구체적 | ① 시나리오에 없는 경우는 검증되지 않음 ② 참여자·시간 부담이 큼 ③ 실제 시스템이 없으면 **모의(mock)로 대체**되어 현실성 저하 | 10월 3개 과제 거버넌스 적용 시뮬레이션, 매뉴얼 워크스루 |
| **T5** | **체크리스트 감사** | S1 진단 · S4 검증 | 판정 기준이 **문항으로 확정**되어 있을 때 | ① 판정이 객관적·재현 가능 ② 수행자 역량 의존도가 낮음 ③ **미충족 항목이 그대로 조치 목록**이 됨 | ① 문항에 없는 위험은 발견되지 않음 ② YES/NO 이분 판정이 **부분 충족을 표현하지 못함** ③ 문항 자체가 낡으면 검증이 무의미 | 가이드라인 점검항목 99개 대조, 보안성 38개 자체 사전점검 |
| **T6** | **벤치마킹** | S2 설계 | 선택지의 **관행 수준**을 알아야 할 때 | ① 설계 대안의 현실성 검증 ② 발주처 설득 근거(다른 곳은 이렇게 한다) ③ 과도·과소 설계 방지 | ① **비교 대상의 맥락이 다르면 오도**(규모·규제·조직구조 차이) ② 공개 정보의 정확성 한계 ③ 관행 추종으로 차별화 상실 | 위험등급 임계값, 위원회 구성·개최 주기, 비용 배분 방식 |
| **T7** | **원가 기반 배분 모형**<br>(ABC 등) | S2 설계 · S4 검증 | 비용을 **활동·사용량 단위로 귀속**시켜야 할 때 | ① 산식이 **원인–결과로 설명됨**(합의 설득력) ② 사용량 변동에 자동 대응 ③ 시산으로 결과를 미리 확인 | ① **계측되지 않는 활동은 배부할 수 없음** ② 원가동인 선정이 자의적일 소지 ③ 모형이 복잡하면 상대방이 검증하지 못해 합의가 지연 | 개발비 배분 비율, 이용료 정산 산식, 공통비·변동비 분리 |

### 2.2 기법 조합의 근거 — 약점 상쇄 관계

기법을 나열하지 않고 **약점이 서로를 메우도록** 배치한 것이 본 방법론의 설계 의도다.

| 약점 | 상쇄하는 기법 | 배치 방식 |
|---|---|---|
| **T1 갭분석 / T2 규제 매핑**의 *"문서에 있으나 작동하지 않는 통제를 충족으로 오판"* | **T4 시나리오 시뮬레이션** | 매핑에서 「충족」으로 판정된 항목 중 **위험등급 高 서비스에 관련된 항목**을 시뮬레이션 시나리오에 강제 포함시켜 실제 작동을 확인한다 |
| **T3 위험평가 워크숍**의 *"참여자 구성에 따른 주관성·쏠림"* | **T5 체크리스트 감사 + T6 벤치마킹** | 워크숍 결과 배점을 AI RMF 예시 배점(합법성 20 / 신뢰성 30 / 신의성실 20 / 보안성 30)과 대조하고, 편차가 큰 부문은 근거를 요구한다. 임계값은 벤치마킹 범위를 벗어나지 않게 한다 |
| **T5 체크리스트 감사**의 *"문항에 없는 위험은 발견되지 않음"* | **T3 위험평가 워크숍** | 체크리스트 수행 후 **"이 문항들로 잡히지 않는 우리 서비스 고유의 위험은 무엇인가"** 를 워크숍 마지막 세션 안건으로 고정한다 |
| **T5**의 *"YES/NO가 부분 충족을 표현 못함"* | **T1 갭분석의 3등급 판정** | 진단 단계에서는 체크리스트를 그대로 쓰지 않고 **충족/부분충족/공백 3등급**으로 판정한다. 부분충족 항목은 그 사유를 함께 기재한다 |
| **T6 벤치마킹**의 *"맥락 차이로 인한 오도"* | **T7 원가 모형의 시산** | 벤치마킹으로 얻은 배분 방식을 그대로 채택하지 않고 **수협 데이터로 시산해 결과를 확인**한 뒤 채택 여부를 판단한다 |
| **T7 원가 모형**의 *"계측되지 않는 활동은 배부 불가"* | **T2 규제 매핑 방식의 계측 대조** | 산식의 모든 변수에 대해 **계측 원천(게이트웨이 로그·클라우드 청구·수동 집계)을 1:1로 매핑**하고, 원천이 없는 변수는 설계 단계에서 제거하거나 대안 배부키로 교체한다 |
| **T4 시뮬레이션**의 *"시나리오에 없는 경우 미검증"* | **T5 체크리스트 감사** | 시뮬레이션 후 점검항목 99개를 다시 대조하여 시나리오가 커버하지 못한 항목을 식별하고, 해당 항목은 문서 검토로 보완 판정한다 |

**요약하면** — 문서 기반 기법(T1·T2·T5)은 **빠르고 재현 가능하지만 형식적**이고, 참여 기반 기법(T3·T4)은 **실질적이지만 주관적·고비용**이며, 참조 기법(T6·T7)은 **설득력이 있지만 맥락 의존적**이다. 세 부류를 단계별로 교차 배치하는 것이 본 방법론의 특징이다.

### 2.3 단계별 기법 배치

| 단계 | 주 기법 | 보조 기법 | 배치 이유 |
|---|---|---|---|
| **S1 진단** | T1 갭분석, T2 규제 매핑 | T5 체크리스트 감사 | 기준선이 명확(점검항목 99개·법령 조항)하므로 재현 가능한 기법을 주로 사용. 단, 3등급 판정으로 이분법 한계를 보완 |

| **S4 검증** | T4 시나리오 시뮬레이션 | T5 체크리스트 감사, T7 시산 | 실제 작동 확인이 목적이므로 시뮬레이션이 주. 시나리오 미커버 영역을 체크리스트로 보완 |
| **S5 이관** | T4(교육 형태로 재사용) | – | 시뮬레이션에서 다룬 실제 케이스를 교재로 전환(SC2-18 대응) |

### 2.4 분석도구 — 실제 산출되는 형태로

도구는 소프트웨어가 아니라 **본 사업에서 만들어져 발주처에 남는 시트·매트릭스·모델**이다.

| # | 도구 | 구조(컬럼) | 사용 단계 | 산출물 귀속 |
|---|---|---|---|---|
| **D1** | **요구사항 추적표** | 요구사항 ID / RFP 원문 / 유형 / Phase / 출처 / 대응 목차 / 반영여부 / 담당 | 전기간 | 별첨1 → 착수 후 검수 기준으로 승계 |
| **D2** | **규범 대조 매트릭스** | 규범 / 조항 / 요구 의무 / 대응 내규 조문 / 대응 상태(충족·부분충족·공백) / 개선과제 ID | S1, S3 | DL1-4 「AI기본법 위반 여부 점검 보고서」의 근거 자료 |
| **D3** | **위험 등급 산정 시트** | 부문(4) / 평가항목(16) / 배점 / 경감방안 / 경감 수행여부 / 잔여위험 비율 / 잔여 점수 / 부문 소계 / 총점 / 등급 | S2, S4 | DL1-3 「위험평가서」의 본문 서식 |
| **D4** | **게이트 체크리스트** | 라이프사이클 단계 / 점검항목 번호 / 문항 / 판정(충족·부분·미충족) / 근거 증적 / 판정자 / 판정일 | S4 | DL2-4 「업무 매뉴얼」의 부속 서식 |
| **D5** | **사용량 계측 모델** | 계측 단위 / 집계 차원(기관·부서/조합·서비스·모델) / 원천 / 수집 주기 / 결측 시 대안 배부키 | S2, S3 | DL4-2 「정산 가이드라인」의 부속 명세 |
| **D6** | **비용 배분 시산표** | 비용 항목 / 공통비·변동비 구분 / 배부 기준 / 기관별 배부액 / 검산 | S2, S4 | DL4-1 「비용 배분 협의서」의 계산예시 |
| **D7** | **기관별 상이 항목 일람표** | 문서 / 조문 번호 / 상이 사유 / 은행 값 / 상호금융 값 | S3 | 각 B형 산출물의 부속 자료 |
| **D8** | **조문 참조 관계도** | 조문 / 참조 대상 조문 / 참조 유형(인용·전제·예외) | S3 | 각 규정류 산출물의 부속 자료 |
| **D9** | **규제 추적 등록부** | 규범·채널 / 조항 / 모니터링 소스 / 주기 / 최근 확인일 / 변경 인지 건수 / 영향도 등급 | 전기간 | Phase2 종료 시 발주처 이관 |

**도구 설계 원칙** — 모든 도구는 **컨설팅 종료 후에도 발주처가 계속 사용하도록** 설계한다. 컨설턴트만 다룰 수 있는 도구는 이관 시점에 사용이 중단되므로, 표 구조를 단순하게 유지하고 각 도구에 **사용 설명 1쪽**을 부속한다.

### 2.5 방법론의 특징 및 장단점 (PD-III-3d)

본 방법론(Ⅲ.3.1의 5단계 + 본 절의 기법 조합)이 갖는 특징과 그 이면의 약점을 함께 제시한다.

| 특징 | 장점 | 단점 | 완화 방안 |
|---|---|---|---|
| **① 정합화(S3)를 별도 단계로 분리** | 접합면 불일치를 검증 전에 해소하여, 검증 결과가 설계 결함인지 접합 결함인지 구분됨 | 단계가 하나 늘어 **일정이 길어짐**. Phase1처럼 짧은 구간에서는 부담 | Phase1에서는 접합면 5개 중 ③계측 요건·④협약 별지 2개만 우선 정합화하고 나머지는 Phase2로 이연 |
| **② 종료조건을 판정 가능한 문장으로 고정** | 단계 종료 여부에 다툼이 없고, 미완 항목이 후행 단계로 흘러들지 않음 | 종료조건 충족에 집착하면 **형식 충족에 시간을 쓰게 됨** | 종료조건은 "미판정 0건" 같은 커버리지 기준으로 한정하고, 품질 판정은 검수 절차에 맡김 |
| **③ 범위를 좁혀 압축 병렬(Phase1 이중 트랙)** | 품질 기준을 낮추지 않고 기한을 맞춤 | Phase1 산출물이 **3개 과제 맥락에 최적화**되어 전사 확장 시 보정이 필요 | Phase2 S1(전수 진단) 결과로 Phase1 산출물의 **적용 범위 확대 개정**을 수행하고, 개정 대상을 착수 시 미리 식별 |
| **④ 문서·참여·참조 3부류 기법 교차 배치** | 각 기법의 약점이 상쇄되어 형식적 충족이나 주관적 판단에 빠지지 않음 | 참여 기법(T3·T4)이 **발주처 인력 부담**을 발생시킴 | 참여 지점을 10개로 한정하고, 각 지점의 소요 시간과 대상을 착수 시 사전 통보하여 일정 확보 |
| **⑤ 도구가 곧 산출물의 일부** | 컨설팅 종료 후에도 도구가 계속 사용됨 | 도구 구조를 단순하게 유지하느라 **분석 정교함을 일부 포기** | 정교한 분석이 필요한 영역(원가 모형)은 계산 로직을 별도 부속하고, 발주처 사용본은 결과 입력·확인용으로 단순화 |

## 3. 제안서용 요약 · 논리 구조

**논리 골격 : [기법 메뉴] → [약점 상쇄] → [단계 배치] → [도구] → [방법론 자체의 장단점]**

- **[기법 메뉴]** 7개 × [적용단계 / 언제 쓰는가 / 장점 / 단점 / 적용 대상]
  - **T1 갭분석** · **T2 규제 매핑** · **T3 위험평가 워크숍** · **T4 시나리오 시뮬레이션** · **T5 체크리스트 감사** · **T6 벤치마킹** · **T7 원가 기반 배분 모형**
  - **단점 칸을 전건 기재** ← PD-III-3d가 「특징 및 장단점」을 명시 요구
- **[약점 상쇄]** 조합 근거 = "많이 쓴다" ✗ / **약점 상쇄 관계** ○ (7쌍)
  - 매핑의 *형식적 충족 오판* → **시뮬레이션이 실제 작동 확인** (충족 판정 + 고위험 서비스 관련 항목은 시나리오 강제 포함)
  - 워크숍의 *주관성·쏠림* → **AI RMF 예시 배점(20/30/20/30) 대조 + 벤치마킹 범위 제한**
  - 체크리스트의 *문항 밖 위험 미발견* → **워크숍 마지막 세션 고정 안건화**
  - 체크리스트의 *YES/NO 한계* → **3등급 판정(충족·부분충족·공백)**
  - 벤치마킹의 *맥락 오도* → **수협 데이터 시산 후 채택 판단**
  - 원가 모형의 *계측 불가 변수* → **변수:원천 1:1 매핑, 원천 없으면 제거 또는 대안 배부키**
  - 시뮬레이션의 *시나리오 미커버* → **사후 점검항목 99개 재대조**
  - 3부류 성격 : 문서 기반(빠름·형식적) / 참여 기반(실질적·주관적) / 참조 기반(설득력·맥락 의존)
- **[단계 배치]** S1 = T1·T2 주 / S2 = T3·T7 주 / S3 = T2 응용 / S4 = T4 주 / S5 = T4 재사용(교육)
- **[도구]** 9종, **소프트웨어 이름 ✗ / 실제 산출되는 시트·매트릭스 ○** — 전건이 산출물의 일부로 귀속
  - D1 요구사항 추적표 · D2 규범 대조 매트릭스 · D3 위험등급 산정 시트 · D4 게이트 체크리스트 · D5 계측 모델 · D6 시산표 · D7 상이 항목 일람표 · D8 조문 참조 관계도 · D9 규제 추적 등록부
  - 원칙 : **종료 후에도 발주처가 계속 쓰도록** 구조 단순화 + 사용 설명 1쪽 부속
- **[방법론 장단점]** 특징 5개 각각에 **단점과 완화 방안 병기** — 정합화 단계 추가(일정↑ → Phase1은 2개 접합면만) / 종료조건 고정(형식 충족 우려 → 커버리지 기준으로 한정) / 압축 병렬(전사 확장 시 보정 → Phase2 확대 개정) / 3부류 교차(발주처 부담 → 참여 10지점 한정·사전 통보) / 도구 단순화(정교함 일부 포기 → 계산 로직 별도 부속)

## 4. 시각적 표현 방안

### (a) 슬라이드 분할 구조 — 2장

- **1장 : `전면 표`** — 기법 비교표 7행 × 6열이 슬라이드 전면. 상단에 단계 축 위 기법 배치도를 얇은 띠로
- **2장 : `상하 2분할`** — 위 = 약점 상쇄 관계도, 아래 = 분석도구 9종 카드 + 방법론 장단점 표

### (b) 도해 지시

**1장 상단 — 단계 축 위 기법 배치 띠**
- 가로 타임라인 : `S1 진단 → S2 설계 → S3 정합화 → S4 검증 → S5 이관`
- 각 단계 위에 해당 기법 태그를 배치. **주 기법은 채워진 태그, 보조 기법은 테두리만 있는 태그**로 구분
- T4(시뮬레이션) 태그는 S4와 S5에 **연결선으로 이어져** 재사용됨을 표시
- 띠 아래에 기법 부류를 색상 범례로 : 문서 기반(T1·T2·T5) / 참여 기반(T3·T4) / 참조 기반(T6·T7)

**1장 본문 — 기법 비교표 전면 배치**
- 7행 × 6열. **「단점」 열의 배경을 다른 색으로 처리**하고 굵은 테두리 — 이 열이 비어 있지 않다는 것이 PD-III-3d에 대한 응답이므로 시각적으로 강조
- 각 행 좌측에 기법 부류 색 띠
- 「장점」·「단점」 열은 번호(①②③)로 항목을 나누어 표기

**2장 상단 — 약점 상쇄 관계도**
- 좌측 열에 7개 기법 노드, 우측 열에도 동일한 7개 노드를 배치(양방향 관계이므로)
- **약점 → 상쇄 기법**을 곡선 화살표로 연결하고, 화살표 위에 상쇄 방식을 짧게 라벨
- 화살표 색은 약점의 성격에 따라 3종 : `형식적 충족`(적) / `주관성`(황) / `범위 누락`(청)
- 중앙에 3부류 원(문서 / 참여 / 참조)을 벤 다이어그램처럼 겹쳐 배치하고, 각 기법을 해당 원 안에 놓는다. **세 원이 모두 겹치는 중앙 영역**에 *"교차 배치"* 라벨 — 이 도해의 결론 지점
- 상쇄 화살표가 **같은 부류 안에서 닫히지 않고 부류를 가로지르는 모습**이 드러나야 한다

**2장 하단 좌 — 분석도구 9종 카드**
- 3열 × 3행 카드 그리드
- 각 카드 : `도구 번호·명칭` / `주요 컬럼 3~4개` / `사용 단계 배지` / `귀속 산출물 배지`
- 카드 하단에 **「종료 후 발주처 계속 사용」 아이콘**을 공통으로 부착

**2장 하단 우 — 방법론 장단점 표**
- 5행 × 4열(특징 / 장점 / 단점 / 완화 방안)
- **「단점」 열과 「완화 방안」 열을 인접 배치**하고 두 셀 사이에 화살표를 그려 대응 관계를 명시

## 5. 인접 절과의 경계 / 인용 근거

### 경계 자기점검

- **Ⅲ.3.1과의 경계** : 5단계(S1~S5)의 정의와 각 단계의 입력·산출·종료조건은 Ⅲ.3.1이 확정했다. 본 절은 **단계를 재정의하지 않고** 각 단계에 배치되는 기법만 다뤘다.
