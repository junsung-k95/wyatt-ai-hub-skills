# SUPERVISOR — 제안서 기술부문 집필 지휘 지시서

수협은행 『AI 거버넌스 실행전략 수립』 제안서 **Ⅲ. 기술부문**을 sub agent 병렬 집필로 작성한다.
이 파일 하나만 읽고 전체를 지휘할 수 있어야 한다.

---

## 1. 구조

**분할 단위: 목차 level 3 소절 1개 = sub agent 1명 = md 파일 1개.**

기술부문 level-3 소절은 **21개**다. 하위 level-4 소절(예: Ⅲ.4.2.1~4.2.6)은 쪼개지 않고, 담당 sub agent가 자기 문서의 **내부 구조**로 전개한다.

```
제안서_작성/
├── _supervisor/                     ← 이 폴더. sub agent에게 주는 공통 자료
│   ├── SUPERVISOR.md                    (이 파일)
│   ├── 01_작성지침.md                    ★ sub agent 필독 — 5개 섹션 구조·금지표현·구체성 기준
│   ├── 02_사업배경_브리핑.md              ★ sub agent 필독 — 배경·Phase·과제간 연결
│   ├── 03_요구사항_원장.md                요구사항 257건 ID→원문
│   ├── 05_취합_체크리스트.md              supervisor 전용 QA 기준
│   ├── manifest.json                    21개 소절 메타데이터 (기계 판독용)
│   └── WORKFLOW_기술부문집필.js           Workflow 실행 스크립트
│
├── 3.1_사업목표및범위/       BRIEF_3.1.1~3.1.4.md  +  3.1.1~3.1.4_*.md
├── 3.2_사업전략및방향/       BRIEF_3.2.1~3.2.6.md  +  3.2.1~3.2.6_*.md
├── 3.3_수행방법론/           BRIEF_3.3.1~3.3.4.md  +  3.3.1~3.3.4_*.md
├── 3.4_수행방안/             BRIEF_3.4.1~3.4.7.md  +  3.4.1~3.4.7_*.md
└── _통합/                    (취합 산출물이 여기 생성됨)
```

**폴더 = 목차 level 2, 파일 = 목차 level 3.** BRIEF와 산출물이 같은 폴더에 나란히 있으므로 sub agent는 자기 폴더만 보면 된다.

## 3. 실행 방법 — 두 가지

### 방법 A. Workflow 스크립트 (권장 · 전체 일괄)

```
Workflow({ scriptPath: "/home/claude/suhyup/제안서_작성/_supervisor/WORKFLOW_기술부문집필.js" })
```

3개 phase가 자동으로 돈다.

| Phase | 에이전트 | 하는 일 |
|---|---|---|
| **Draft** | 21 | 소절별 BRIEF를 읽고 원고 집필 → 지정 경로에 저장 |
| **Verify** | 3 | ① 금칙어·구조·커버리지 ② 경계 중복 ③ 과제 간 정합성 — 독립 축으로 병렬 검증 |
| **Integrate** | 2 | 통합본 / 거버닝메시지 스토리라인 / 시각화 계획표 / 미해결 이슈 생성 |

**일부만 다시 돌리기** — `args`에 목차 번호 배열을 넘긴다.

```
Workflow({ scriptPath: "...WORKFLOW_기술부문집필.js", args: ["3.4.2","3.4.3","3.4.4","3.4.5"] })
```

동시 실행은 런타임이 자동으로 제한한다(약 10~16개). 21개를 넘겨도 전부 완료된다.

### 방법 B. Agent 도구 직접 호출 (부분 재작업 · 중간 개입)

한두 소절만 다시 쓰거나, 결과를 보며 지시를 바꿔가며 돌릴 때.

```
Agent({
  description: "3.4.2 과제1 집필",
  prompt: "다음 3개 파일을 순서대로 읽고 원고를 작성해 지정 경로에 저장하라.
           1) /home/claude/suhyup/제안서_작성/_supervisor/01_작성지침.md
           2) /home/claude/suhyup/제안서_작성/_supervisor/02_사업배경_브리핑.md
           3) /home/claude/suhyup/제안서_작성/3.4_수행방안/BRIEF_3.4.2.md
           요구사항 원문은 _supervisor/03_요구사항_원장.md 에서 확인하라.
           규제 근거는 Projects 도구의 project_search 로 원문을 검색해 조항 단위로 인용하라."
})
```

여러 소절을 동시에 돌릴 때는 **한 메시지 안에 Agent 호출을 여러 개** 넣는다. 그래야 병렬로 실행된다.

## 4. sub agent에게 반드시 전달할 3가지

1. `_supervisor/01_작성지침.md` — 5개 섹션 구조, **금지 표현**, 구체성 판정 기준
2. `_supervisor/02_사업배경_브리핑.md` — 사업 배경, Phase 구조, 과제 간 연결
3. 담당 `BRIEF_*.md` — 미션 질문 / 필수 포함 항목 / 담당 요구사항 전수 / **경계** / 시각화 방향

이 3개를 안 읽히면 일반론이 나온다.

## 5. 각 md 파일의 고정 구조

```
# [목차번호] [소절 제목]
> 메타 | 요구사항: ID... | Phase | 예상 분량

## 1. 거버닝 메시지        헤드메시지 1문장(주장형) + 서브메시지 2~3
## 2. 본문                수행 가능한 수준. 이 파일의 존재 이유
## 3. 제안서용 요약·논리 구조  슬라이드에 올릴 형태로 압축 + 논리 골격 명시
## 4. 시각적 표현 방안      (a) 슬라이드 분할 패턴 (b) 도해 지시 (c) 표·차트 사양
## 5. 인접 절과의 경계 / 인용 근거   경계 자기점검 + 규제 조항 출처 + [가정] 목록
```

**슬라이드 분할 패턴**은 아래에서 골라 명시하게 되어 있다 —
`3분할 가로 열거` · `4분할 세로 흐름` · `좌우 2분할 비교` · `상하 2분할` · `중앙 다이어그램 + 주변 설명` · `전면 표`

## 6. 취합 시 점검 순서

`05_취합_체크리스트.md`를 따른다. 요약하면:

1. **형식** — 21개 파일 존재 / 5개 섹션 / 메타 줄
2. **커버리지** — BRIEF의 요구사항 ID가 본문에서 실제로 다뤄졌는가 (나열만 하면 반려)
3. **금칙어** — `가능하다` 류 발견 시 문장 단위 반려
4. **경계 중복** — 6개 취약 쌍 확인 (3.1.3↔3.2.2 / 3.2.5↔3.3.4 / 3.2.6↔3.4.4 / 3.3.3↔3.4.6 / 3.4.2↔3.4.3 / 3.4.4↔3.4.5)
5. **정합성** — 위험등급 체계, 계측 단위↔정산 변수, 역산 일정↔제출 시기, 라이프사이클 단계 명칭
6. **시각화** — 같은 분할 패턴이 3절 연속 반복되지 않는가
7. **통합 산출** — `_통합/` 4개 파일

## 7. 알아둘 것

- **BRIEF는 고쳐도 된다.** 발주처 미팅이나 질의응답으로 새 정보가 들어오면 BRIEF의 `2. 반드시 본문에 들어가야 할 것`에 추가하고 해당 소절만 재집필한다.
- **분량은 목표치지 할당량이 아니다.** 구체성이 분량보다 우선한다.
- **Ⅳ.사업관리부문 / Ⅴ.지원부문 / Ⅰ.제안개요는 이 스캐폴드에 없다.** 기술부문이 확정된 뒤 같은 방식으로 확장한다 — `sections.py`에 소절을 추가하고 `build_scaffold.py`를 다시 돌리면 폴더·BRIEF가 자동 생성된다.
- **Ⅲ.1.4(요구사항 대응 총괄표)** 는 이미 만들어진 요구사항 추적표(257건)를 압축하는 절이다. 새로 조사할 것이 없으므로 가장 빨리 끝난다.
- **재생성 주의**: `build_scaffold.py`는 `제안서_작성/` 폴더를 통째로 지우고 다시 만든다. sub agent가 쓴 원고가 있으면 먼저 백업할 것.
