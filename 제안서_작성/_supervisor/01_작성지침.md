# 작성지침 — 모든 sub agent 공통 규칙

## 0. 너의 산출물은 무엇인가

**제안서 슬라이드의 원고**다. 완성된 슬라이드가 아니라, 슬라이드를 만들 사람이 그대로 받아쓸 수 있는 원고.
따라서 **내용의 구체성**과 **시각화 지시**가 둘 다 있어야 한다.

## 1. 파일 구조 — 5개 섹션 고정

작성하는 md 파일은 반드시 아래 5개 섹션을 이 순서로 갖는다. 섹션 제목을 바꾸지 말 것.

```
# [목차번호] [소절 제목]

> **메타** | 요구사항: `ID, ID, ...` | Phase: ... | 예상 분량: N장

## 1. 거버닝 메시지
## 2. 본문
## 3. 제안서용 요약 · 논리 구조
## 4. 시각적 표현 방안
## 5. 인접 절과의 경계 / 인용 근거
```

### 1. 거버닝 메시지
- 이 소절 전체를 **한 문장**으로 압축한 헤드메시지. 슬라이드 상단에 그대로 올라간다.
- 사실 서술이 아니라 **주장**이어야 한다. ("~을 수립한다" ✗ / "~ 때문에 ~ 방식으로 수립해야 한다" ○)
- 아래에 서브메시지 2~3개를 bullet로. 각 서브메시지가 본문의 한 덩어리에 대응한다.

### 2. 본문
- **실제로 프로젝트를 수행할 수 있는 수준**으로 쓴다. 이게 이 파일의 존재 이유다.
- 판정 기준: 이 글을 읽은 컨설턴트가 **다음 주 월요일에 무엇을 할지 알 수 있는가?**
- 구체적이라는 것의 의미:
  - 프로세스를 쓸 때 → 단계 / 수행 주체 / 입력 / 산출 / 소요일 / 판정기준을 다 적는다
  - 규정을 쓸 때 → 조문 목차 수준으로 적는다
  - 평가체계를 쓸 때 → 항목 · 배점 · 산식 · 등급 임계값을 적는다
  - 산식을 쓸 때 → 변수를 정의하고 숫자 예시로 한 번 계산해 보인다
  - 조직을 쓸 때 → 직위 수준으로 적는다 (실명 금지)
- **선택지가 있는 사안은 결론만 던지지 말고 선택지를 먼저 깔고 비교한 뒤 권고안을 낸다.**
  형식: `옵션 A / B / C → 각각 언제 쓰는가 · 장점 · 단점 → 수협 적용 시 권고안과 근거`
- 문장은 **주어·동사·목적어를 끝까지** 쓴다. 명사 던지기 금지.
  ✗ "게이트키핑 체계 구축" → ○ "라이프사이클 4개 단계마다 체크리스트 통과 여부를 판정하는 승인 게이트를 설치한다"

### 3. 제안서용 요약 · 논리 구조
- 본문을 **슬라이드에 올릴 형태로 압축**한 것. 본문의 복사가 아니라 구조화된 축약.
- 논리 전개를 명시: `[문제 인식] → [원인] → [해법] → [실행] → [효과]` 중 이 소절이 어떤 골격인지 밝히고 그 골격대로 배열.
- bullet · 화살표(→) · 볼드로 구조화하되 **내용을 삭제하지는 말 것.**

### 4. 시각적 표현 방안
반드시 아래 3가지를 모두 적는다.

**(a) 슬라이드 분할 구조** — 이 소절을 몇 장으로 나누고 각 장을 어떻게 쪼갤지
사용 가능한 분할 패턴을 명시적으로 골라 쓸 것:
- `3분할 가로 열거` — 병렬 항목 3개 (원칙, 유형, 영역)
- `4분할 세로 흐름` — 순차 프로세스
- `좌우 2분할 비교` — As-Is/To-Be, 은행/상호금융, 옵션 대비
- `상하 2분할` — 위=구조도, 아래=설명표
- `중앙 다이어그램 + 주변 설명` — 아키텍처, 조직도
- `전면 표` — 매트릭스, 비교표, 목록

**(b) 도해 지시** — 무엇을 그릴지 그리는 사람이 바로 그릴 수 있게
도형·축·라벨·화살표 방향·강조 지점까지 지정. 예: "가로축=라이프사이클 10단계, 게이트는 마름모, 승인권자를 마름모 아래 배지로, 위험등급 高 경로는 굵은 적색 선"

**(c) 표·차트 사양** — 표는 컬럼 목록과 행 예시 2개까지, 차트는 차트 종류·축·계열

### 5. 인접 절과의 경계 / 인용 근거
- BRIEF의 `경계` 항목을 지켰는지 자기 점검. 인접 절로 넘긴 내용이 있으면 명시.
- 프로젝트 파일(가이드라인·AI RMF·보안 안내서)에서 인용한 조항을 **출처와 함께** 목록화.
- 사실이 불확실해 가정으로 쓴 부분은 **`[가정]` 태그**를 붙여 명시. 숨기지 말 것.

## 2. 절대 금지

| 금지 | 이유 |
|---|---|
| "가능하다", "검토한다", "고려하고 있다", "할 수 있을 것 같다", "제공할 수 있다" | **RFP가 평가 시 '불가능'으로 처리한다고 명시함** |
| RFP 문장을 그대로 옮겨 적기 | 요구를 반복하는 것은 답이 아니다. **어떻게 충족시킬지**를 써라 |
| 프로젝트 맥락 없는 일반론 ("AI 거버넌스란 ~") | 비생산적. 항상 수협 맥락에 붙여 쓸 것 |
| 설명 없는 표·용어 투척 | 읽는 사람이 모르는 용어는 풀어 쓴다 |
| BRIEF의 `경계`를 넘어 인접 절 내용 쓰기 | 취합 시 중복이 생긴다 |
| 실존 인물 실명, 확인되지 않은 수치 | 실명은 직위로, 미확인 수치는 `[가정]` |

## 3. 분량

BRIEF의 `예상 분량(N장)` 기준. 슬라이드 1장 ≒ 본문 400~600자 + 요약 + 시각화 지시.
**분량을 채우려고 늘리지 말 것.** 구체성이 분량보다 우선한다.

## 4. 저장

- 저장 경로와 파일명은 BRIEF 상단에 지정되어 있다. **그 경로에 그 이름으로** 저장한다.
- 다른 파일을 만들거나 다른 소절의 파일을 건드리지 않는다.
