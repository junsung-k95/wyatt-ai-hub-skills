# 취합 체크리스트 — supervisor 전용

sub agent 산출물을 받은 뒤 이 순서로 점검한다.

## A. 형식 점검 (자동)

- [ ] 21개 파일이 모두 존재하는가
- [ ] 각 파일에 5개 섹션(거버닝 메시지 / 본문 / 요약·논리구조 / 시각적 표현 / 경계·근거)이 모두 있는가
- [ ] 메타 줄에 요구사항 ID가 기재되어 있는가

## B. 커버리지 점검

- [ ] 각 파일이 BRIEF에 지정된 요구사항 ID를 **본문에서 실제로 다뤘는가** (ID 나열만 하고 내용이 없는 경우 반려)
- [ ] 기술부문 매핑 요구사항이 빠짐없이 다뤄졌는가

## C. 금칙어 점검 (자동)

다음 표현이 하나라도 있으면 **해당 문장을 반려**한다. RFP가 평가 시 '불가능'으로 처리한다고 명시한 표현이다.

`가능하다` `가능함` `할 수 있을 것 같` `고려하고 있` `고려중` `검토 예정` `제공할 수 있` `~할 수도`

## D. 경계 중복 점검

아래 쌍은 내용이 겹치기 쉽다. 겹치면 **뒤쪽 절에서 삭제하고 앞쪽 참조**로 바꾼다.

| A | B | 판정 기준 |
|---|---|---|
| 3.1.3 Phase 우선순위 | 3.2.2 데드라인 역산 | A=우선순위 논리, B=역산 캘린더·임계경로 |
| 3.2.5 위험요소 | 3.3.4 유사프로젝트 해결방안 | A=이 사업 위험 레지스터, B=경험 기반 해법 카탈로그 |
| 3.2.6 시스템 구축방향 | 3.4.4 과제3 아키텍처 | A=기술 선택지 비교, B=목표 아키텍처 설계·로드맵 |
| 3.3.3 산출물 체계 | 3.4.6 산출물 목록·소유권 | A=제출 시기 중심, B=내용·권리 중심 |
| 3.4.2 과제1 위험평가 | 3.4.3 과제2 게이트 | A=평가 체계 자체, B=게이트에서 호출만 |
| 3.4.4 계측 메트릭 | 3.4.5 정산 산식 | A=무엇을 어떻게 세는가, B=센 것으로 얼마를 나누는가 |

## E. 정합성 점검 (내용)

- [ ] 과제1의 위험등급 체계와 과제3의 가드레일 자동 적용 대상이 같은 등급 체계를 쓰는가
- [ ] 과제3의 사용량 계측 단위와 과제4의 정산 산식 변수가 일치하는가
- [ ] 3.2.2의 역산 일정과 3.3.3의 산출물 제출 시기(D+n)가 모순되지 않는가
- [ ] 은행/상호금융 이원 처리 방식이 전 절에서 일관된가
- [ ] 라이프사이클 단계 명칭이 3.4.3과 3.4.4에서 동일한가

## F. 시각화 점검

- [ ] 모든 파일에 슬라이드 분할 패턴이 지정되어 있는가
- [ ] 같은 패턴(예: 4분할 세로 흐름)이 연속 3개 절에서 반복되지 않는가 → 반복되면 변화 지시
